# v0.3i — Fix: Follow-up Retention Counter Mis-Scoped to Chunk, Not Panelist

I wrote this fix as a design record up front, the same way I did for v0.3g.
No separate decisions doc exists for this slice or for v0.3h before it, so both are recorded here, with v0.3h's note prepended since this fix grew directly out of the measurement run that slice describes.

## Prior slice: v0.3h call-count instrumentation (no separate doc)

Counter lives at the provider boundary (captures retries by construction); total + per-stage tally stamped into the export payload alongside prompt_version.
Measured against a real session: 12 calls / 4 turns — 3 setup (gate, extraction, persona) + 2×4 turns + 1 narrative.
Verdict: matches the stated budget arithmetic.
This measurement run is also what surfaced the DA retention bug this doc fixes.

## The bug (characterized from the instrumented run, evidence on record)

`follow_ups_on_current_topic` (`models/session.py:40-54`) counted trailing turns sharing `chunk_index` regardless of who asked.
`_generate_da_question` deliberately reuses the contested turn's chunk (`engine.py:288`).
So when Devil's Advocate contests a turn on a chunk where a prior panelist already exhausted `MAX_FOLLOW_UPS_PER_TOPIC`:

1. `_should_follow_up` denies DA any follow-up chain of its own (the v0.3f retention mechanic silently never runs for DA), and
2. `session_is_complete` (`engine.py:170-178`) terminates the session for a reason unrelated to either documented end condition (DA answered strongly / DA's own chain hit the cap).

Reproduced live: 4-turn session, all turns on chunk 51, DA scored 1/1/1, DA's own chain length 1, yet the session ended.
Most likely to trigger when answers are uniformly weak — i.e. against the users the app exists to serve.

## The fix (locked)

v0.3f's semantics are per-panelist floor retention.
Rescoped the counter: it now counts trailing consecutive turns where BOTH `chunk_index` AND the asking panelist (`panelist_archetype_key`) match the current context.
DA arriving at another panelist's exhausted chunk starts at 0 and gets its full chain; `session_is_complete` evaluates DA's own chain, exactly as its docstring already promises.

Implementation constraints and how they were met:

- **Call-site audit before changing anything.** Exactly one production consumer of `follow_ups_on_current_topic` exists: `_should_follow_up` at `engine.py:156`.
  `used_chunk_indices` is a separate, unaffected property (chunk variety for rotation/retrieval exclusion, not the retention cap) — not touched.
  One test consumer, `test_branching.py`'s `test_followups_counted_per_chunk_not_globally`, uses a single panelist throughout, so its assertions hold unchanged under the new scoping.
  No consumer needed the old chunk-only meaning preserved under a distinct name.
- **Attribution field confirmed before writing the fix.** `ConversationTurn.panelist_archetype_key` (`models/session.py:16`, v0.3b) already exists and is queryable — no inference from turn position or archetype guessing was needed.
- **No prompt/template changes.** `PROMPT_VERSION` did not move.
- **No changes to scoring, retrieval, panel composition, the gate, or the call counter.**

## Tests (synthetic fixtures, zero LLM calls)

Added to `tests/test_engine.py`, alongside the existing `select_active_panelist` / `session_is_complete` suite:

1. `test_da_not_blocked_by_another_panelists_exhausted_chunk_regression_shape` — exact reported repro shape: panelist M exhausts the cap on chunk 51, DA's next turn contests that claim on the same chunk.
   Asserts DA's `_should_follow_up` is NOT blocked by M's spent follow-ups, and `session_is_complete` is False at DA's first turn given a weak answer.
2. `test_da_own_chain_reaching_cap_ends_session` — DA's own chain reaching the cap DOES end the session.
3. `test_da_answering_strongly_ends_session` — DA answering strongly DOES end the session.
4. `test_non_da_retention_still_caps_per_panelist_on_one_chunk` — non-DA retention unchanged: a panelist's own consecutive follow-ups on one chunk still cap correctly.
5. The one consumer found in the call-site audit (`test_followups_counted_per_chunk_not_globally`) was checked explicitly — it uses a single panelist throughout, so it behaves identically under the new scoping without modification.

## Implementation deviations from the design record

1. **New script added, not an existing one reused.** No script in `scripts/` drove a full multi-turn session end-to-end against a real provider — `probe_question_gen.py` and its siblings exercise individual question/scoring calls against hand-built session fixtures, not a full `select_active_panelist` → `_generate_question` → `_score_answer` → `session_is_complete` loop.
   I wrote `scripts/repro_da_retention_scope_fix.py` for the live re-run, following the same real-provider/real-document pattern as the existing probes.
2. **Report narrative call included in the live re-run**, though the evidence bar only asked about turn count and end condition.
   Included it to keep the run's call-count shape comparable to the real export flow and to v0.3h's original 12-call tally.
3. **`test_branching.py`'s stale docstring comment updated** (it described the pre-fix chunk-only semantics) for accuracy — not a functional change, and not one of the five specified tests, but left uncorrected it would misdescribe the property's new behavior right next to the tests that exercise it.
