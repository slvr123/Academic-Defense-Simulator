# v0.3d-pre — Follow-up Attribution Fix: Decisions + Code Session Brief

**Status:** LOCKED — 2026-07-12
**Scope:** One defect fix: `FOLLOWUP_SYSTEM_PROMPT`'s false first-person claim when
rotation hands a follow-up to a different panelist than the one who asked the
original question. Confirmed live via `engine.py` source read (see
`v0.3d-defense-ui-decisions.md` → Decision 3 and Carried defect).
**Sequencing:** This session runs **before** the 0.3d UI session. 0.3d inherits the
corrected prompt set and makes zero further prompt changes.
**Format note:** decisions and brief combined in one doc (Day 5 precedent) — the
change is small enough that splitting them adds ceremony, not clarity.

---

## The defect, precisely

`select_active_panelist` is a pure function of `turn_num` — rotation advances every
turn regardless of content. `_should_follow_up` decides whether to press a prior
weakness with zero knowledge of who speaks next (its own docstring: "any panelist
may press a weakness surfaced by whoever went before them"). When both fire across
a rotation boundary, `FOLLOWUP_SYSTEM_PROMPT` renders for Panelist B:

> "You previously asked the candidate this question: {previous_question}"

…where the question was asked by Panelist A. The model is instructed to claim, in
first person, an exchange it (in character) never had. Post-0.3b this happens on
**most** follow-ups, not edge cases — with a panel of N, a follow-up lands on the
same panelist only when the follow-up chain wraps a full round, which the
`MAX_FOLLOW_UPS_PER_TOPIC = 2` cap makes rare for panels of 3+.

**In plain terms:** the script hands Dr. Okafor a line that begins "as I asked you
earlier" about a question Dr. Reyes asked. A careful reader of any transcript will
catch it. The fix makes the prompt tell the truth: when it's a colleague's
question, say so.

---

## Decision 1 — Mechanism: injected framing block, single template (LOCKED)

No second template. The "You previously asked..." passage in
`FOLLOWUP_SYSTEM_PROMPT` becomes a `{prior_exchange_framing}` slot, assembled in
`engine.py` exactly like `other_subtype_line`, `digest_block`, and
`{high_difficulty_guard}` already are — established pattern, no new machinery.

Two framing variants (exact wording final unless Code hits a rendering problem, in
which case flag, don't improvise):

**Same asker** (`previous_turn.panelist_archetype_key == active.archetype_key`) —
today's wording, verbatim, unchanged:

```
You previously asked the candidate this question:
"""
{previous_question}
"""

The candidate answered:
"""
{previous_answer}
"""
```

**Colleague case** (keys differ):

```
Your fellow panelist, Dr. {previous_panelist_name}, asked the candidate this question:
"""
{previous_question}
"""

The candidate answered:
"""
{previous_answer}
"""

You are now taking the floor. Press on the identified weakness from your own
lane's perspective — do not simply repeat your colleague's question or imitate
their framing.
```

`{previous_panelist_name}` comes from `previous_turn.panelist_name` — the
denormalized field 0.3b added for exactly this class of use (digest rendering
without a panel lookup). Zero schema changes.

The downstream acknowledgment instruction ("open with ONE short, natural spoken
acknowledgment...") stays untouched — it reacts to the candidate's answer, which
is true in both variants.

**In plain terms:** instead of two near-identical scripts to keep in sync, the one
script gets a fill-in-the-blank section, and Python picks the truthful version of
the blank. The project already does this three times elsewhere; this is the fourth.

---

## Decision 2 — Branch condition and placement (LOCKED)

- Condition: `previous_turn.panelist_archetype_key == active_panelist.archetype_key`.
  Compare **archetype keys**, not names — names are denormalized flavor; the key is
  identity.
- Placement: a small pure function in `engine.py` (suggested:
  `_render_prior_exchange_framing(previous_turn, active_panelist) -> str`) called
  where the follow-up prompt is assembled. Pure string-in/string-out — a zero-LLM
  pytest target.

## Decision 4 — Re-verification: mandatory probe re-run, follow-up path only (LOCKED)

Day 4's standing rule: wording changes silently invalidate earlier verification.
The follow-up path's evidence base predates this change, so it re-runs. Scope kept
minimal — the new-topic path has a zero-word diff and does not re-run.

- `scripts/probe_question_gen.py`, DAZSMA doc, follow-up path only.
- **Minimum 4 follow-up generations: at least 2 colleague-case, at least 2
  same-asker.** The colleague case needs a panel of ≥2 with a scripted weak answer
  so rotation naturally hands the follow-up across panelists; if the existing probe
  harness can't force asker≠presser, extend the harness (fixture-level, not
  engine-level) — flag whatever extension was needed.
- Per row, record the existing fields plus a new `framing_case`
  (`"same_asker"` / `"colleague"`), `is_grounded()` boolean, and the human-judged
  nulls per the standing pattern.
- Results to a **new** JSONL (`probe_followup_attribution_results.jsonl`) —
  committed, per the v0.2.5 precedent (human-judged probe files are irreplaceable).
- Pass bar for the colleague case, checkable from raw output: (1) no first-person
  claim of having asked the prior question; (2) the question still presses the
  identified weakness; (3) `grounding_reference` still quotes the source document
  (the Miss-2 rule holds).

## Call budget (standing constraint 2)

**Probe only: ~8–12 flash-lite calls** (each follow-up row costs a real turn:
question + score + follow-up generation; 4 rows ≈ 12 calls at worst). Session
call structure is otherwise unchanged — the fix itself adds zero calls; 2T+1
stands.
