## 1. What changed, per slice

### Slice 1 - retrieval follow-up

**In plain language.**
After Chapter 1, the backend now looks for a line that is only "References", "Bibliography", "Literature Cited" or "Works Cited".
If it's in the second half of the document, everything from that heading to the next appendix, CV or glossary heading (or the end) is cut before the text is split into passages.
The text above the heading on its page stays, and so do the appendices.
New-topic questions no longer always take the single best passage: they pick at random among passages that score within 0.02 of the best, with the dice fixed by the session and the turn.

**H1, code.** `backend/page_filter.py`: `reference_range`, `trim_references`, and `chunk_pdf_filtered` (renamed from M5's `chunk_pdf_without_navigation`; `trim_reference_list=False` is M5's chunker, kept for the eval's before run).
`backend/pdf_ingest.py` logs `reference list left out of chunking: page N to M|the end` (page numbers only).
20 new tests in `backend/tests/test_page_filter.py`: the synthetic PDF with Chapter 5 text above a References heading, a reference list, then an appendix; an early "Literature Cited" chapter; no references heading; no end heading; the scanned check over all text; heading and end-heading tables; the trim at both ends and on one page.

**H1, removed ranges.**

### Slice 2 - reliability

**In plain language.**
If the answer to "Start the defense" gets lost, pressing Start again gets the same first question back, with no new Gemini call and no second slot.
If you answer from a tab that's behind, the screen moves to the question the panel is actually on, keeps what you typed, and says so.
The "You've used your N defenses" message now uses the number the server sends.
The App-level tests have 15 s to finish instead of 5.

- **H4.** `/start` stores its response (`Defense.start_response`) and replays it while no answer is in; after that, 409 `already_started`.
  The client resends `/start` on a plain 409 every 3 s, up to 10 times, as it does for answers, and then shows "The panel is still preparing this defense. Try again in a moment."
  This replaces D16's swallow, which left the screen preparing for good.
- **H5.** `GET /sessions/{id}/current` returns `{done, question}` under the turn lock.
  On `stale_question`, the client calls it and moves to the open question with the notice "This answer was for an earlier question. You're now on question N.", the typed text kept and the last evaluation cleared.
  If `/current` fails, the stale message shows as before.
- **H6.** The `per_ip_limit` 429 body carries `limit` (`CodedHTTPException(..., limit=...)`; other error bodies are unchanged, via `exclude_none`).
  The copy reads it; with no `limit` (an older server) it says "You've used this network's defenses for today."
- **H7.** `vi.setConfig({ testTimeout: 15_000 })` at the top of the four `App.*.test.tsx` files; everything else keeps the defaults.
  The backend sweep test's deadline is 15 s.
  No retries anywhere.
  The cascade didn't reproduce: forced timeouts of 250 ms and 400 ms on the two biggest App files gave failures that were each that test's own timeout (17 of 18 at 250 ms, 8 of 8 at 400 ms; the 18th was the per-IP copy test I then updated for H6).
  So there was no cause in our setup to fix (deviation 11).

New tests: `backend/tests/test_start_replay_and_current.py` (5), updated `test_defense_api.py`'s 409 test and `test_client_ip.py`'s 429 test; frontend `flow.test.ts`, `client.test.ts` and `App.defense.test.tsx` (`/start` resend after 409, `already_started`, the per-IP limit of 5, the stale resync and its fallback).
`npm run gen:api` was run after each schema change.

### Slice 3 - voice latency

**In plain language.**
The server can now voice a question one sentence at a time, and the browser plays sentence one while fetching sentence two.
It's off unless `ADS_TTS_SPLIT_SENTENCES` is true.
While it's off, the browser still asks for "part 0", gets the whole question as the only part, and behaves exactly as before.

- **H8.** `/tts` logs `tts session=… turn=N part=k/n archetype=… chars=… bytes=… ms=…`, and on failure the same fields; never the text (tested).
- **H9.** `backend/tts_split.py`: a pure sentence splitter (splits at `.`, `!` or `?` before a capital, digit or quote; not after e.g., i.e., et al., Dr., Fig. and similar, or inside decimals; pieces under 20 characters join a neighbour; at most 8 parts).
  `POST /tts` takes an optional `part` (0-7, else 422); with the flag on it voices that sentence and returns `X-TTS-Parts`; past the last part is 404.
  Limits are per part: 2 synth calls each.
  CORS exposes `X-TTS-Parts`.
  The client (`useQuestionVoice`) fetches part 0, plays it, fetches part n+1 while part n plays, and plays on; Replay plays every part again from cache.
  A part 0 failure falls back to the browser voice, as before (E8); a later part's failure stops there.
  Tests: `test_tts_split.py` (14), `test_tts_parts.py` (8), `App.voice.test.tsx` (3 new: order and prefetch, a later part failing, revoking every part), `client.test.ts` (`X-TTS-Parts` parsing).
- **Driver.** `scripts/e2e_defense.py --voice-calls N` voices each question part by part, as the client does, within a MiMo budget (2 new tests).

## 2. Rule outcomes and deviations

**H2 (H1's rule).**
- **sample3: pass.** Criterion 1: 0 of 8 top-1 picks and 0 of 18 session turns on removed reference text (before: 2 and 1). Criterion 2: removed p77 line 1 to the end; 0 changes outside the range. Criterion 3: navigation picks 0; Check A Differentiated → Differentiated; max displacement 2.
- **DAZSMA: filter not applied** (no bare references heading), which H2 says is not a pass. Its retrieval is unchanged.
- H1 stays in.

**H3.** The final eval's pooled near-tie rate is **62.5%** (DAZSMA 4 of 8, sample3 6 of 8): the **"above 50%" branch**, so seeded near-tie sampling is adopted and live.

**H10.** Median time to first audio **7.14 s** (H8; the live run's was 5.80 s), so the latency condition is met.
The listening condition is mine (checklist item 1).
Until then the flag stays **off**: H10's first branch needs both, and the merge keeps production off either way.

**Deviations, with provenance:**
1. **H1's end heading also accepts a titled appendix heading** ("Appendix A – Survey Instrument", "Appendix C: Interview"), and rejects one with dotted leaders or a titled one ending in a page number.
   Read strictly, "only an Appendix heading" would miss DAZSMA's style of appendix heading, and on a document with references before such appendices the filter would delete every appendix, which H1 says must stay.
   Matching too much only ends the cut early, leaving some references in: the fail-open direction.
2. **H1 needs a front-matter boundary.** "After the front-matter boundary" has no meaning without one, so with no Chapter 1 heading nothing is removed, as with the navigation filter.
3. **What counts as "reference text" in H2.** A chunk counts only if it reaches the reference pages and contains a removed line of 20+ characters.
   Text alone over-counted: sample3's body chunks quote some reference lines word for word (tables cite their sources, URLs included), which first put 4 session turns on references instead of the true 1.
4. **The H3 band is strict:** `best - score < 0.02`, the same "near-tie" Check B counts.
5. **The v1 edit is the parameter plus the import its type needs and a docstring.** 5 lines added and 1 changed in `engine.py`; the default resolves `retrieve` at call time so `tests/test_engine.py`'s monkeypatch of `engine.retrieve` still works.
6. **The seeded Check E assumes no follow-ups,** so new-topic turn n is turn n, as the top-1 Check E does.
   Live sessions seed by their real turn numbers (1, 4, 7 above), which the live replay confirmed.
7. **H4's client** resends `/start` on a plain 409 every 3 s up to 10 times, the same constants as answers, then shows a notice; `already_started` shows the server's text and is never resent.
8. **H5's endpoint takes the turn lock,** so it answers 409 while a turn is running rather than read a defense mid-update; the client then shows the stale message as before.
9. **H6's fallback copy** for a 429 without `limit`: "You've used this network's defenses for today."
10. **The splitter merges pieces under 20 characters** into a neighbour and caps at 8 parts by joining the tail; H9 asked for a deterministic sentence splitter and these are its rules.
11. **Test hangs and stale caches.**
    The first backend baseline run hung for over 30 minutes and I killed it; seven later runs took 83 to 148 s, so I couldn't reproduce it or find a cause.
    Separately, the repo's `__pycache__` folders still held pytest's rewritten bytecode from the OneDrive location, so a traceback named `C:\Users\Asus\OneDrive\...`; modules all resolved from `C:\Code` (checked), and I deleted those caches.
    The H7 cascade didn't reproduce either (slice 2 above).
12. **H8 measured direct to MiMo, from my machine.** Only M3's questions were usable: the M3b doc kept no response bodies.
    For a one-part question, the first audio is the same request as the whole question, so it isn't measured twice.

## 3. Concepts map

- **Heading-based vs layout-based detection.**
  Layout-based detection judges a page by its shape, like most lines ending in a page number; heading-based detection looks for one specific line, like a bare "References".
  A heading is a stronger signal but only catches documents that word it that way, which is why DAZSMA's "Appendix H – References" slipped through (`backend/page_filter.py:61` `is_navigation_page` vs `:42` `_REFERENCES_HEADING` and `:100` `reference_range`).
- **Seeded randomness and reproducibility.**
  A random generator started from a fixed seed always produces the same "random" choices, so a seed built from (session id, turn number) gives each turn its own pick that can be replayed exactly.
  That's how the eval and I could recompute the live run's pages offline (`backend/retrieval_sampling.py:27` `turn_seed`; `backend/defense.py:228`).
- **Why sampling only among near-ties costs no relevance.**
  The pick is restricted to passages within 0.02 of the best score, and at that distance the embedding can't tell them apart (M4's near-tie threshold).
  Anything clearly better can never be passed over, so the worst case is a 0.02 drop, and the eval measured 0.0188 (`backend/retrieval_sampling.py:41`).
- **Replaying a response vs re-running the work (H4 vs M3b's E13).**
  Replaying means storing the answer the server already sent and sending it again; re-running would call Gemini and reserve a slot a second time, and might produce a different question.
  `/start` now does what `/answers` has done since E13: the stored response comes back for a resend (`backend/defense_routes.py:184` for `/start`, `:241` for answers).
- **A resync endpoint.**
  When a client's picture of the state is out of date, a resync endpoint lets it ask the server where things actually stand instead of guessing or reloading.
  `GET /current` returns the open question, and the client jumps there after a stale answer (`backend/defense_routes.py:220`; `frontend/src/state/useFlow.ts:148`).
- **Feature flags controlled by env vars.**
  The code for a feature ships switched off, and an environment variable turns it on without changing or redeploying the code.
  That lets me decide on split voices after listening, on Render's dashboard (`backend/settings.py:65`; `backend/defense_routes.py:288`).
- **Prefetching the next audio part while the current one plays.**
  Starting the next request while sentence one is still playing hides that request's wait inside the playback time.
  If sentence two takes less time to make than sentence one takes to say, the listener hears no gap (`frontend/src/voice/useQuestionVoice.ts:78`).
