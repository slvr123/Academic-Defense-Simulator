### L2. The fix: only the Literature & Theory Specialist may draw literature-review passages
- **Every other retrieving panelist** skips chunks that M7's `page_filter` tagged as literature review (full or partly). Their search acts as if those chunks don't exist. Follow-ups reuse a panelist's own previous chunk, as today. The Devil's Advocate doesn't retrieve.
- **The Literature & Theory Specialist** (`literature_theory_specialist`) keeps access, subject to L5's verdict.
- **Implementation:** through the M6 injectable `retriever` seam, composed with M6's seeded near-tie sampling. **No change to `academic_defense_simulator/`.** If the retriever can't tell which panelist is asking without a v1 change, derive the panelist from the query: v1 uses each archetype's fixed `archetype_focus` string as the query. A test asserts those strings are unique. Any other v1 change → stop.
- **Untagged documents behave exactly as today**: no tags, nothing skipped. A test proves the engine input is byte-identical.

*Downside I accept:* panels without a Literature Specialist (the recommended capstone panel among them) never ask about the literature review, and lose "why didn't you adopt X from your own review?" questions. Chapters 1 and 3 still mention prior work.

### L3. A sharper note for the Literature Specialist
Keep the M8 note and append the cited authors detected in that chunk (M7's citation patterns): *"Researchers cited in this excerpt: Kim et al. (2025), Yarkan (2025), …. Their systems are not the candidate's. Ask how the candidate used, compared against or departed from them."* This applies only to tagged chunks, so in practice only the Literature Specialist sees it. If a chunk has no detected authors, use the M8 note unchanged.

### L4. Offline verification (zero LLM calls), pre-committed
Re-run M4's eval (M6 seeded mode, 360 seeded turns per document) on sample3, DAZSMA and the bundled anicheck sample. All of these must hold:
1. **Zero** top-1 picks and zero session turns on tagged chunks for every archetype except the Literature Specialist.
2. Check A doesn't move to a worse branch on any document; Check E max displacement stays at 5 or below; navigation and reference picks stay at 0.
3. DAZSMA (no tags) is byte-identical to M8's results.

Any failure → stop. Don't merge.

### L5. The Literature Specialist probe, judged independently
- **Items:** the Literature Specialist on each of sample3's 14 tagged chunks (plus the bundled sample's 1), difficulty 3, with L3's note on: **15 items**.
- **Judge:** a **separate fresh agent** spawned in the Code session, given only the rubric below and the sheet (question, passage, pages). It must not see this doc, the M7/M8 docs, the note's wording or the code. It writes a label and a one-line reason per item. Its output is the verdict; Claude spot-checks it in chat afterwards.
- **Rubric (verbatim to the judge):** *M if the question presupposes the candidate built, adopted, runs or selected a system or technique that the passage attributes to cited researchers, with no basis in the passage; C if it treats the candidate's own work as cited; OK otherwise; ? if genuinely ambiguous.* `?` counts as M.
- **Verdict (pre-committed):**
  - **M ≤ 1 of 15 → the Literature Specialist keeps access** (`ADS_LIT_REVIEW_ACCESS=literature`).
  - **Otherwise → no panelist draws literature-review passages** (`ADS_LIT_REVIEW_ACCESS=none`). Literature questions wait for v2.1.
- Either way the routing ships. Code sets the setting's default to the verdict's value before merging, so I have nothing to flip.
