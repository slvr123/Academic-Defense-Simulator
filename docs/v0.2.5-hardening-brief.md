## Task 2 — Programmatic grounding check *(zero LLM calls)*

Standing hallucination detector: `grounding_reference` must actually come from the
turn's `chunk_text`. Runs every turn, both question paths, permanently.

**Placement:** new module `academic_defense_simulator/grounding.py`, one pure
function. Not in the retriever (which stays persona/LLM-ignorant), not in the
provider (which stays transport-only). Called from the loop right after a
`PanelistQuestion` is parsed.

**Spec:**

```python
def is_grounded(reference: str, chunk_text: str, threshold: float = 0.85) -> bool:
    """True if `reference` appears in `chunk_text`, exactly or fuzzily.

    1. Normalize both: lowercase, collapse all whitespace runs to single spaces,
       strip.
    2. Exact-substring check first — if normalized reference is in normalized
       chunk, pass immediately (cheap path; expected common case per Day 2's
       verified verbatim references).
    3. Fallback: slide a window of len(reference) across the chunk (step =
       max(1, len(reference) // 4)), compute difflib.SequenceMatcher(None,
       reference, window).ratio() per window, pass if max ratio >= threshold.
    """
```

**On failure:** `logging.warning` with both strings (reference + a bounded excerpt
of the chunk, not the full chunk). **Do not fail the session** — a grounding miss is
signal to collect, not a crash. No retry, no re-generation.

**Call sites:** the shared point in the loop where both new-topic and follow-up
questions land after parsing — one call site if the loop shape allows, not two
copies.

**Verify:** forced-failure run — feed a fabricated reference against a real chunk,
paste the warning output; plus one real turn showing the pass path (can be covered
by Task 4's probe run).

## Task 4 — Question-generation probe to the Day 3 bar *(~10–14 flash-lite calls)*

The open item from `day4_decisions.md`: question generation runs on flash-lite but
was only sanity-checked. This is the formal re-verification.

**Must cover both prompt paths — new-topic AND follow-up.** Earlier reasoning about
grounding leaned on Day 2's "genuinely verbatim" finding, but that evidence is v0.1
only — `FOLLOWUP_SYSTEM_PROMPT` didn't exist yet, and the later acknowledgment/tonal
naturalness pass (post-v0.2) pushes follow-up-path `grounding_reference` toward
paraphrase, in tension with exact-quote grounding. This is the same defect already
tracked as an open backlog item ("`grounding_reference` semantic divergence between
follow-up and new-topic turns") — this probe is where it finally gets real evidence
instead of staying a suspicion.

**Script:** `scripts/probe_question_gen.py`. On the DAZSMA capstone PDF (same doc as
Day 2/5 — keeps evidence comparable):

- **New-topic path:** minimum 4 questions across ≥ 3 distinct chunks (use
  `exclude_indices` to force chunk variety), spanning at least two `difficulty_level`
  values (e.g. 2 and 4).
- **Follow-up path:** minimum 2 questions, forced deliberately — for each, run a real
  turn: generate a new-topic question, submit a scripted weak-but-not-blank answer
  (reuse the Day 5 weak-answer pattern) that produces a `primary_gap` and fails the
  "strong" branching gate, then generate the resulting follow-up question. This is
  the only way to actually exercise `FOLLOWUP_SYSTEM_PROMPT` — it cannot be sampled
  cold like the new-topic path.
- `methodology_expert` only — same archetype as all prior evidence; adding archetypes
  adds variables, not signal, at this stage.
- Per question, record raw JSON to `scripts/probe_question_gen_results.jsonl`:
  the full model output, chunk index, requested difficulty, **`path`
  (`"new_topic"` or `"follow_up"`)**, plus:
  - **(a) grounded** — automated: run Task 2's `is_grounded()` on each result against
    the correct `chunk_text` (the re-injected prior chunk on the follow-up path, per
    `day3_decisions.md` §5), record the boolean and (on fuzzy path) the ratio.
  - **(b) in-lane** and **(c) difficulty-appropriate** — human-judged: leave fields
    in the JSONL for Sean to fill (`"in_lane": null, "difficulty_ok": null`), or
    record them live if Sean is driving the session. Not model-judged — no LLM
    grading LLM here.
- If Task 1 found the lane-fix re-verification already recorded in
  `day5_eval_results.md`, cite it in the results file header; the probe's (b) column
  then confirms rather than establishes.
- **Expect follow-up-path grounding ratios to run lower than new-topic.** That's the
  finding, not a bug in the check — log it plainly in the results file. Do not tune
  the `0.85` threshold or touch `is_grounded()` mid-session on the strength of this
  alone; a fix (path-aware threshold, broader match scope, or a prompt change) needs
  its own design decision, not a silent patch inside this probe.

**Verify:** paste the raw JSONL (or its head + line count), the pass/fail tally for

   export time, not carried as session state.

   export_payload = {

       "Download transcript",

       file_name=f"defense_session_{session.profile.document_id}.json",

   Available at session end state; fine to expose mid-session if trivial, but
   end-state only is sufficient.
4. Zero business-logic changes. The UI import boundary holds: `streamlit_app.py`
   imports `PROMPT_VERSION` from the prompts module — no business-logic module

## Confirmed decisions (locked by Sean, 2026-07-08)

1. **Fuzzy-match threshold: `0.85`.** Not a final guess — Day 2 already showed
   `grounding_reference` coming back genuinely verbatim, so the fuzzy path is a
   safety net for minor formatting drift, not a tool for accommodating real
   paraphrasing. Task 4's probe is where this actually gets tuned: look at the real
   ratios computed for any non-exact-match case in the JSONL and adjust from
   evidence, not another guess.
2. **`prompt_version` is export-time only.** `DefenseSession` stays untouched; the
   constant is wrapped around the dumped session dict only inside
   `streamlit_app.py`'s download handler (see Task 5, item 3). Simpler, no
   models/prompts coupling. Tradeoff: session persistence in v0.4 will need its own
   decision on where the tag lives, since it isn't carried on the model.
3. **`PROMPT_VERSION` initial value: `"0.2"`.** v0.2.5 makes zero prompt/rubric
   wording changes, so the current prompt set is still exactly what Day 4 rewrote
   and Day 5 tuned. Moves only the next time template or rubric wording changes.
4. **Probe results file (`probe_question_gen_results.jsonl`) gets committed.**
   Different case from the gitignored `eval_run_*.log`s — those were raw stdout
   already condensed into the permanent `day5_eval_results.md` summary, so the raw
   log was disposable once that summary existed. The probe JSONL has no summary
   standing in for it, and once the human-judged `in_lane`/`difficulty_ok` columns
   are filled in it's irreplaceable — re-running the probe produces different
   flash-lite output, not the same file. Commit as-is; no separate summary needed.
5. **`pytest` goes in `requirements.txt`.** Means Streamlit Cloud installs it on
   deploy too — harmless, just marginally heavier than strictly necessary. Not
   worth a separate dev-requirements file for one package.
