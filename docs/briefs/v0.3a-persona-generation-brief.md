## Task 3 — Persona generation call + fallback *(2–3 live calls; fallback forced)*

- `PERSONA_GENERATION_PROMPT` — exact template from the decisions doc (Decision 2),
  lives in the prompts module. `{archetype_roster}` renders one line per archetype:
  `- {archetype_key}: {archetype_title} — {archetype_focus}` from
  `ARCHETYPE_CONFIG`.
- Generation orchestration in `panel.py`:
  `generate_panel(profile: DefenseProfile, archetype_keys: list[str], provider) -> tuple[list[Panelist], bool]`
  — returns the panel plus a `fallback_used` flag. Goes through the existing
  provider abstraction; no new provider-specific code outside it.
- **Post-parse validation (Python, not model trust):** output keys must match the
  requested roster exactly — same keys, same count, no unknowns, no duplicate
  surnames. Order mismatch alone → reorder in Python to roster order, not a
  failure. Any other violation → treat as malformed response.
- **Failure behavior:** retry once, then fall back to `FALLBACK_PANELISTS` (exact
  dict from the decisions doc — Reyes/Okafor/Tanaka/Alvarez), sliced to the
  requested roster, `logging.warning` emitted, `fallback_used = True`. This is the
  locked departure from 5a's fail-clean rule — do not fail the session on persona
  failure.

Tests in `tests/test_panel.py` (pure, mocked provider): unknown key → fallback;
missing key → fallback; duplicate surname → fallback; order mismatch → reordered,
no fallback; valid response → passthrough with `fallback_used=False`.

**Verify:** (a) one real generated panel's raw JSON pasted from a live call
(thesis profile, panel_size 3); (b) fallback path forced — state the mechanism
(mocked provider returning malformed JSON twice) — warning output and the
resulting fallback panel pasted; (c) pytest green.
