## Part 3 — Audible group harness (third commit)

**Purpose:** make DoD 5's listening half performable without restarting the app. The
listening judgment stays Sean's; this session builds the instrument only.

**Why not restart the app:** hearing nine profiles does not require a defense session.
Restarting costs a fresh ingest plus per-turn API calls to hear the same synthesis the
probe can already produce for free.

### 3.1 — Audible mode behind a flag

Extend `scripts/probe_voice_resolution.py` with an audible mode — query param or
equivalent, e.g. `?audible=1`.

Default behaviour must be unchanged. `speak()` stays stubbed by default so the existing
mechanical resolution run remains exactly reproducible against the committed evidence.
Confirm this explicitly.

### 3.2 — Play co-seatable groups, not nine in a row

This is the part that determines whether the harness tests the right thing.

Decision 5 scoped the requirement to per-panel separation. Nine voices played
sequentially is an easier discrimination task than two alternating in conversation — a
sequential run would pass while the real condition fails.

- Derive the groups from the actual panel composition logic, not from a hardcoded
  list. Read it from source and paste the derived groups.
- Include `devils_advocate` in every group it actually appears in — per the last
  session it is appended to every roster, so confirm that from source rather than
  taking it on trust.
- Within a group, play the seated archetypes alternating, the way they would speak in
  a session — not blocked one after another.

### 3.3 — Controlled text

Every archetype speaks the same fixed sentence — one neutral line of roughly twelve to
fifteen words, identical across all of them. Varying the text confounds voice
discrimination with content discrimination.

### 3.4 — Show what resolved

For each archetype as it speaks, display: archetype key, the voice name that actually
resolved, and the pitch and rate applied. Sean needs to note which pair was
indistinguishable, not just that one was.

### 3.5 — Same code path

The harness must drive `_voice_component_html`. No parallel or simplified copy of the
resolution chain — a harness that diverges from the shipped path tests nothing.
