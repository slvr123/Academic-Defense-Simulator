## Task 5 — Dev-view toggle (Decision 4)

`st.toggle` gating an expander. Contents per turn: full `AnswerScore` (clarity,
depth, grounding, difficulty_delta, primary_gap), `grounding_retry_used`,
`grounding_flagged`, current `difficulty_level`, and session `PROMPT_VERSION`.

**Nothing from that list renders anywhere in the main flow mid-session** — this
now explicitly includes `difficulty_level` (Decision 4 item 3). Difficulty
appears to the user only in the report's trajectory after session end.

**Verify:** (a) screenshot toggle-on showing all fields; (b) screenshot of the
same turn toggle-off — zero score/difficulty/flag signals anywhere; (c)
`PROMPT_VERSION` visible reading `0.3d`.

## Task 6 — Aborted-state copy (Decision 5)

Three fixed stage-keyed messages via `st.error()`:
- question-gen: "The panel's next question took longer than expected."
- scoring: "Scoring your answer took longer than expected."
- report-build: "Building your report took longer than expected."

Plus one action: "Start a new session". No retry-in-place. Raw `abort_message`
goes to logs (already does, via lifecycle logging) and dev-view only. Reuse the
existing `label` passed to `_call_with_timeout` as the stage key if it's already
distinguishing (check first); otherwise add an `abort_stage` session-state key —
Streamlit layer only.

**Verify:** force each of the three call sites (state mechanism — e.g.
`LLM_CALL_TIMEOUT_SECONDS` temporarily lowered, restored before commit; paste the
restore diff). Screenshot each message; paste the log line showing the raw
exception text landed in logs, not on screen.

## Task 7 — Report view (Decision 6)

Rendered from `session.report` at session end, top to bottom:
1. Narrative (or "Narrative unavailable this session" when
   `narrative_fallback_used`)
2. Difficulty trajectory as the plain text sequence ("2 → 3 → 3 → ...")
3. Three session averages
4. Per-panelist sections, composition order, card visual language: name,
   archetype, turns_taken, three averages, `primary_gaps` verbatim
5. Pushback events table: turn, `difficulty_from → difficulty_to`, outcome enum
   verbatim (`recovered`/`held`/`deteriorated`). Zero-escalation renders "No
   escalation moments this session".

No number computed in the UI — everything reads off `DefenseReport` fields.

**Verify:** screenshot from a real session's report; force or replay (state
which) the zero-escalation and narrative-fallback states, screenshot both.
