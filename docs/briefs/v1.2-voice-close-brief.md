## Input 3 — The listening pass was not performed

**Record it that way. Do not record it as passed.**

DoD 5's by-ear half remains open. The pre-committed decision rule's branch D
applies: *"I can't reliably judge — record as unverified rather than passing it
on a vibe."*

The reason this matters more now, not less: accepting same-gender voice reuse
means at least one male pair will be separated by pitch and rate on an
**identical** voice. That is exactly the condition that measured 0.07 apart and
prompted the whole correction. Asserting those pairs are distinguishable would
be asserting the single claim there is most reason to doubt.

Decision 5 must therefore say, in substance: *the by-ear separation pass was not
performed. Per-panel distinguishability is assumed adequate and is not verified.
The shared-voice male pairs are the specific case most likely to fail.*

verdict and Code records it instead of the not-performed note. **Nothing in this

## Part 1 — Probe fix (small, but it invalidated a measurement)

The resolution probe reported **"0 voices installed"** on a run where the
browser demonstrably had 26. `getVoices()` was read before it populated — the
async quirk the shipped component already handles via `voiceschanged`
(Decision 4, step 1). The probe does not, or not reliably.

That is a probe bug, not a product bug, but it means probe output can silently
understate the inventory and produce an all-`(browser default)` table that looks
like a map failure.

1. Add the `voiceschanged` re-read to the probe, matching the component.
2. Extend the dump to report the **full inventory** — `name`, `lang`,
   `localService` — not only what resolved.
3. Re-run in Chrome and paste. It must again report the 22 voices in the
   committed evidence. If it reports zero, the fix didn't take.

## Part 2 — Values pass on `VOICE_PROFILES`

Values only. **No change to the resolution chain, the speech component, the
`sessionStorage` guard, or the escaping helper.** Those are verified and
committed.

### 2.1 — Allocation rule

**Female archetypes — four distinct voices, no reuse:**

Aria (en-US), Libby (en-GB), Hayley (en-AU), Priya (en-IN). Accent separates far
better than pitch, so this group is comfortable. Heather and Zira are spares.

**Male archetypes — three voices, two reuses:**

- **Gorilla avatar → David.** Lowest voice available; pair with the lowest pitch
  and slowest rate in the map. Deep and unhurried is the whole effect. Legacy
  quality is an advantage here, not a cost.
- **Guy (the only neural male) → the archetype heard most often.**
  `devils_advocate` joins every roster, so if its avatar is male, it takes Guy.
  If not, pick by default-panel frequency, computed — not guessed.
- **Remaining three male archetypes** split across Guy / David / Mark.

### 2.2 — Choosing which pairs share

**Compute this, don't pick it.** Use `coseatable_groups()` to count
default-panel co-occurrence for every male archetype pair, and assign so the two
reused pairs are the ones that co-occur **least**. Paste the co-occurrence
counts alongside the chosen assignment.

Reused pairs get maximum pitch and rate separation — nothing resembling the
0.07 gap that started this.

### 2.3 — Preserve Chrome behaviour

Edge names are **prepended**. Every existing entry stays below them. Chrome
misses the new names and falls through to current behaviour. Backward compatible
by construction — confirm by re-running the probe in Chrome and showing the
resolutions are unchanged from the committed evidence.

### 2.4 — Tests

- The three existing collision tests must still pass unchanged.
- **Add one test, but measure before writing it.** The intended property is:
  within each of the six default panels, every seated archetype's
  *first-preference* voice name is distinct. **This may be unsatisfiable** — if
  any default panel seats four male-avatar archetypes, four distinct male voices
  are needed and only three exist.

  So: first paste the per-default-panel gender counts. If the strict property
  holds, assert it. If it does not, assert the weaker achievable property —
  *at most one shared-voice pair per default panel, and shared pairs have a
  pitch gap ≥ 0.30* — and record in Decision 5 why the strict form was
  unreachable.
- **Falsify first**, as with the last session's collision tests: show the new
  test failing against the current map before it passes against the corrected
  one.
