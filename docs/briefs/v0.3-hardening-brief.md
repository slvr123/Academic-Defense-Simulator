## Task Block 1 — Hang-closure carryover

Full spec lives in `docs/v0.3-hang-investigation-closure.md`, Decision 2 and
its disposition table. Restated as concrete tasks:

### 1a. Timeout guard
Wrap the per-turn LLM call path in the driver layer (`streamlit_app.py`)
with a timeout — order of 120s. On trip: clean user-facing error state
("something went wrong — refresh to continue"), session fails clean per
5a's existing rule. This is a tripwire against infinite silence, not a
latency SLO — don't tune it tighter without evidence it needs to be.

### 1b. Thin permanent call-lifecycle logging
Driver-layer logging, left in the shipped app (unlike Phase 1's temporary
hang-investigation instrumentation): timestamp, thread id, a call counter,
one line before each LLM call (*started*) and one after (*returned*). Light
enough to run in production; the only purpose is giving any future
recurrence something to look at.

### 1c. `sleep(13)` → 5s trim
Both call sites. Run **one** full browser session post-trim; zero 429s
required. If a 429 appears, revert to 13s and record the finding in the
session report — do not iterate on the pacing value.

### 1d. `build_report` driver wire-up
`streamlit_app.py` calls `build_report(session)` at session-end, same as the
CLI driver already does (0.3c). Browser exports currently carry
`report: null`; this closes that gap. Driver orchestration only — zero
changes to `report.py` or `engine.py`. Import boundary holds.

### 1e. ROADMAP edits
Mark v0.3a complete (Task 8 closed — Code's run 4 + Sean's 3 manual browser
sessions satisfy the "full browser session" criterion). Record the gate
conversion: "root-caused and fixed" → "bounded and observable," pointing to
`v0.3-hang-investigation-closure.md`. Note this hardening session as
current. Note the deployment-gate confirmation is still owed from Sean.

**Verify (1a–1e):** timeout guard forced (mock/injected fault, mechanism
stated) showing the clean error state; one full call-lifecycle log excerpt
pasted; the post-trim session's raw output showing zero 429s (or the
revert + finding); one exported transcript JSON showing populated
`session.report` from a browser session; ROADMAP diff pasted.

## Task Block 2 — Difficulty-4/5 fabrication fix + Miss 3

### 2a. `is_grounded()` enforcement escalation
In the loop, immediately after a `PanelistQuestion` is parsed and
`is_grounded()` is checked (existing call site, v0.2.5): if
`difficulty_level >= 4` and the check fails, issue **one** retry — same
chunk, same `difficulty_level`, a fresh generation call on the same prompt
path (new-topic or follow-up, whichever produced the failing question). Do
not re-retrieve. Below difficulty 4: unchanged, warn-and-log only (existing
v0.2.5 behavior, don't touch).

### 2b. Prompt fix
Add `HIGH_DIFFICULTY_GROUNDING_GUARD` (exact text in the decisions doc,
Decision 3) as a new `{high_difficulty_guard}` slot in both
`PANELIST_SYSTEM_PROMPT` and `FOLLOWUP_SYSTEM_PROMPT`. Populated only when
`difficulty_level >= 4`, empty string otherwise. Bump
`PROMPT_VERSION`: `"0.3c"` → `"0.3c-hardening"`. Confirm and state in
verification notes: zero wording diff outside this one addition.

### 2c. Schema additions
`ConversationTurn` gains:
```python
grounding_retry_used: bool = False
grounding_flagged: bool = False
```
Both `False` unconditionally below difficulty 4. `grounding_retry_used =
True` when 2a's retry fires; `grounding_flagged = True` only if the retry
*also* fails `is_grounded()` — served anyway, this turn is the flagged one.

### 2d. Miss 3 — verify before fixing
Re-extract the DAZSMA PDF via current `chunk_pdf`. Locate a chunk containing
a page-number artifact. Determine directly from that output: standalone
line (strip it — safe) or interleaved mid-sentence (needs a narrower
pattern that doesn't risk eating a real number like a sample size). Only
after this confirmation, apply the fix in `chunk_pdf`. State which pattern
was found, with the actual excerpt, in the session report — this is
Decision 8's evidence-first requirement, not optional.

### 2e. Probe extension
Add `forced_difficulty: Optional[int] = None` to `probe_question_gen.py` —
overrides computed `difficulty_level`, injected directly into both prompt
paths' `{difficulty_level}` slot.

Run:
- **New-topic:** ≥ 4 questions, forced across difficulty 4 and 5, ≥ 3
  distinct chunks (`exclude_indices` to force variety).
- **Follow-up:** ≥ 2, forced via real turns (question → scripted weak
  answer, reusing the Day 5 weak-answer pattern → score → follow-up
  question), forced difficulty 4/5.
- **DA fixture:** ≥ 2 generations against a small hand-built synthetic
  digest (one clear, strong prior claim — construct it inline in the probe
  script, not from a live session), forced difficulty 5, DA persona/prompt
  path.

Output: `scripts/probe_question_gen_v0.3_hardening_results.jsonl`. Per row:
full model output, chunk index, requested difficulty, `path` (`new_topic` /
`follow_up` / `da_fixture`), automated `is_grounded()` boolean + ratio, and
two `null` human-judged fields for Sean to fill:
`content_fabricated_despite_grounding` (all rows) and
`digest_claim_fidelity` (`da_fixture` rows only).

### 2f. Decision gate (Decision 1's resolution procedure)
This is not optional cleanup — it is how task block 2 is declared done or
not. After 2e's probe completes: **do not auto-conclude.** Present the
JSONL (or its head + line count) with the pass/fail tally for
`is_grounded()` broken out by `path`, and explicitly flag any row where
fabrication is visually apparent even before Sean's human-judged columns are
filled in (state this as your own observation, not a substitute for Sean's
judgment). If you observe or suspect a case of
`content_fabricated_despite_grounding` — content asserting something not in
the excerpt while `grounding_reference` still technically passes — **say so
explicitly and do not mark task block 2 complete.** That is the STOP
condition from Decision 1; report it, don't route around it.

**Verify (2a–2f):** `is_grounded()` retry forced (mock/injected fault,
mechanism stated) showing the retry firing and `grounding_retry_used`/
`grounding_flagged` set correctly on both single- and double-failure cases;
prompt diff pasted showing the new slot and zero diff elsewhere; Miss 3's
real corruption excerpt pasted before the fix, and the fixed chunk after;
full probe JSONL (or head + line count) with the by-path tally; `pytest`
green including new tests for 2a/2c/2d.
