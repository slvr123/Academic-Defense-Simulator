## Task 2 — `report.py` aggregates *(zero LLM calls)*

New module `academic_defense_simulator/report.py`. Pure functions, no streamlit
import, no provider import except in the narrative function (Task 3).

Required functions (names indicative, signatures Code's call — keep them small
and single-purpose):

1. **Trajectory extraction** — per-turn `difficulty_level` sequence from
   `session.turns`, in order. This is the difficulty the candidate *faced* each
   turn — confirm against how the engine records it; if the stored field
   semantics are ambiguous, flag rather than guess.
2. **Quality sum** — `clarity + depth + grounding` for a scored turn (3–15).
3. **Pushback classification** — per decisions doc §Decision 1, exactly:
   - Event at every turn *t* (t ≥ 1) where trajectory[t] > trajectory[t−1]
   - Outcome precedence: `recovered` first (sum improved **or** sum_at ≥ 11 —
     import/reuse the existing strong-answer constant from `_should_follow_up`'s
     home; do **not** re-declare the literal), then `held` (|Δ| ≤ 1), then
     `deteriorated` (Δ < −1)
   - Zero escalations → empty list, no placeholder
4. **Per-panelist attribution** — sections in composition order
   (`session.panel` order), averages over that panelist's scored turns only,
   `primary_gaps` = every non-null gap in turn order. A panelist with zero
   turns still gets a section (`turns_taken=0`, averages 0.0, empty gaps) —
   the report must reflect the panel that sat, not just who spoke.
5. **`build_report(session) -> DefenseReport`** — composes 1–4, then the
   narrative step (Task 3).

Skipped/unanswered turns: if any turn lacks a score (shouldn't happen post-5a,
but don't assume), exclude it from averages and quality sums, and flag in
verification notes if the live run produces one.

**Verify:** covered by Task 4's tests — no separate evidence needed here beyond
the module existing with zero streamlit imports (grep output pasted).

## Task 3 — Narrative call + fallback *(structure zero-call; live calls in Task 5)*

1. **`REPORT_NARRATIVE_PROMPT`** — new template in the prompts module. Content
   per decisions doc §Decision 3: input is the report JSON (dumped **minus**
   `narrative` and `narrative_fallback_used`); instruct: summarize from the
   provided data only; do not invent facts, scores, or events not present in
   the data; address the candidate directly ("you"); target 150–250 words;
   **plain text output, not JSON** — no parse step, empty/whitespace-only
   response counts as a failure.
2. **`PROMPT_VERSION` bumps `"0.3b"` → `"0.3c"`.** No wording change to any
   existing template — state in verification notes that the diff outside the
   new template is zero (same pattern as 0.3a's scoring-prompt note).
3. **Failure behavior** per §Decision 4: on timeout / API error / empty
   response → retry once → on second failure, `narrative=None`,
   `narrative_fallback_used=True`, `logging.warning`. **The session never
   fails over the narrative.** Wrap at the provider boundary consistent with
   5a's placement — but note the divergence from 5a's fail-clean outcome is
   locked and documented; do not "fix" it to fail-clean.
4. **Engine integration** — engine calls `build_report(session)` once after
   the final turn, assigns to `session.report`. CLI driver (`main.py`) prints
   the numeric report at session end (plain formatting, no new dependency).
   `streamlit_app.py`: **no change** beyond whatever already serializes the
   session — the report rides `model_dump_json()` automatically. Confirm the
   export payload needs zero changes; if the export code path strips unknown
   fields somehow, flag.

**Verify (structure):** forced-fallback run — mock/monkeypatch the provider to
raise twice (state the mechanism), paste the warning output and the resulting
report JSON showing `narrative: null, narrative_fallback_used: true`.

## Task 4 — Tests *(zero LLM calls)*

`tests/test_report.py` (split files if cleaner). All pure, no API, no network,
no `.env`. Build synthetic `DefenseSession` fixtures by hand — do not load PDFs
or the embedding model.

Required cases:

1. Trajectory extraction correctness on a hand-built 4-turn session.
2. Pushback classification: one fixture per outcome (`recovered` via improved
   sum; `held`; `deteriorated`), **plus** the recovered-precedence case (sum
   dipped but sum_at ≥ 11 → `recovered`, not `held`/`deteriorated`), **plus**
   zero-escalation → empty list, **plus** boundary: |Δ| exactly 1 → `held`,
   Δ exactly −2 → `deteriorated`.
3. Per-panelist attribution on a synthetic 2-panelist session: averages
   correct per panelist, gaps in order, zero-turn panelist gets an empty
   section.
4. Averages: overall averages match hand-computed values; unscored turn
   excluded (if Task 2's skip rule applies).
5. Narrative fallback: provider mocked to fail twice → flag set, narrative
   None; provider succeeds on retry → narrative populated, flag False.
6. Strong-threshold reuse: test asserts the classification uses the same
   constant as `_should_follow_up` (import it in the test — this pins the
   "no second threshold" decision).

**Verify:** full `pytest` output pasted — all new tests green **and** the
existing 85 still green, with total count.

specific-and-defends-a-limitation) — deliberately include at least one weak
answer early to give the difficulty room to escalate, or the run risks a
