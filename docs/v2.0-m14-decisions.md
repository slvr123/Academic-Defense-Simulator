## Decision 1: Detect chapters at ingest (product code)

M12's chapter map existed only in `scripts/measure_opening_order.py`. M14 promotes it into product code.

- **Where.** In `backend/page_filter.py`, next to the existing heading logic. Reuse `_lines` and `is_navigation_page`.
  - It returns `chapter_starts: dict[int, int] | None`, mapping chapter number to its 0-based start page.
  - The result is stored on the ingested document so every defense on it can use it.
- **Heading rule** (same as M12's eval):
  - A non-navigation page with exactly one `CHAPTER n` heading line starts chapter n. Arabic, roman or word numerals all count.
  - The heading must be a heading, not prose. Use the same "bare, or a title after a separator, or in capitals" test as `_CHAPTER_THREE_HEADING`, generalized to any number.
  - Only the first occurrence of each number counts.
  - Pages before Chapter 1 are chapter 0.
- **Validity.** Return `None` (no map) unless all of these hold:
  - chapter 1 is present;
  - at least 3 chapters are detected;
  - start pages strictly increase with the chapter number.

  When the map is `None`, everything below is skipped and behavior is exactly as today.
- **Chunk chapter.** A chunk's chapter is the chapter of its `page_start`. That matches what the M12 measurement scored.
- **Agreement test.** The product detector must produce the same maps the M12 eval script recorded:
  - AniCheck `{1: 4, 2: 6, 3: 8, 4: 11, 5: 14}`, 1-based as printed;
  - sample3 `{1: 5, 2: 13, 3: 43}`.

  Show the output. If either map differs, that's **STOP POINT A**: report the difference and don't proceed.
- **Refactor the eval script.** It must call the product detector after this change, so there is one copy of the rule.

## Decision 2: Restrict each panelist's opening question to its home chapter

**Scope.** Only a domain panelist's **first** question in a session, which is always a new-topic retrieval.

Everything else is untouched:
- follow-ups (they reuse their chunk and don't retrieve);
- the Devil's Advocate (it contests an earlier chunk and doesn't retrieve);
- every later new topic.

Round two onward behaves exactly as now.

**Mechanism.** It works through the M9 retriever seam, with no v1 change.
- In `_next_question`, a panelist with no earlier turn in `session.turns` gets an extra exclusion set: every chunk whose chapter is not the panelist's target chapter.
- That set is added to `exclude_indices`, the same way `RoutedRetriever` adds blocked chunks.
- Near-tie sampling then runs unchanged over whatever remains.
- Put it in a small module (`backend/chapter_filter.py`) with pure functions, as `routing.py` does.

**Target chapter** = `min(HOME_CHAPTER[key], max detected chapter)`.
- The clamp exists for short documents. sample3 has 3 chapters, so the Results reviewer (home 4) targets Chapter 3, where sample3's results actually are.
- There is no separate chapter table: `HOME_CHAPTER` in `opening_order.py` stays the single source.

**Order of precedence. This is the rule that protects M9.**
1. M9 routing blocks literature-review chunks first. The chapter filter **only narrows and never unblocks.**
2. The chapter exclusion is added on top.
3. **Fallback:** if routing plus the chapter filter plus the usual exclusions leave no candidate chunk, drop **only** the chapter exclusion and retrieve as today. Routing and the usual exclusions stay.
   - The expected case is the Literature Specialist (home 2) under `lit_review_access=none`, where Chapter 2 is fully blocked. It falls back, and M9 wins.

**Flag.** `ADS_OPENING_CHAPTER_FILTER` (bool) in `settings.py`, following the `ADS_ATTRIBUTION_NOTES` pattern. Its default is decided by the measurement below. The env var on Render can turn it off without a deploy.

**Logging.** On each opening question, log one line: archetype key, target chapter, whether the filter applied or fell back (and why: no chapter map, or no candidates), and the chosen chunk's page. No passage text.

## Decision 5: Neon idle connection (M12 Flag 7)

In `backend/quota.py`, change `ConnectionPool(min_size=1, ...)` to `min_size=0`. Keep `max_size` as is.

- **Why.** With `min_size=1`, the pool keeps one connection alive and replaces it about every hour (`max_lifetime=3600`). Opening that replacement through Neon's proxy can wake a suspended compute. With the pinger keeping the backend up 18 hours a day, that's up to ~18 pointless wakes a day against Neon's free 100 CU-hours per project per month. With `min_size=0`, idle connections close after `max_idle` and nothing reconnects in the background.
- **Downside accepted.** The first quota call after idle opens a fresh connection. Neon would have been suspended by then anyway (it scales to zero after 5 idle minutes), so a wake was coming regardless.
- **Verify.**
  - Show that `psycopg_pool` 3.3.3 accepts `min_size=0`.
  - Add a test that after `open()` and an idle period the pool holds 0 connections, using `get_stats()` or the pool's size, with time faked or shortened.
  - Run the existing quota tests.
  - If `TEST_DATABASE_URL` is set in `backend/.env`, also run `backend/tests/test_quota_db.py` and show 0 skipped. If it isn't set, say so. Don't treat it as a failure.
