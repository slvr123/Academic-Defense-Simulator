## 1. D1 - chapters detected at ingest

`page_filter.chapter_heading_number()` generalizes `_CHAPTER_THREE_HEADING`'s test to any arabic, roman or word numeral: a heading is bare, or has a title after a separator, or a title in capitals.
Prose ("Chapter 3 describes ...") and contents lines (dotted leaders, or a title ending in a page number) aren't headings.
`page_filter.chapter_starts()` skips navigation pages (`is_navigation_page`) and lets a page with exactly one heading line start that chapter, counting only the first page for each number.
It returns `None` unless Chapter 1 is present, at least 3 chapters are, and start pages strictly increase.
`chunk_pdf_filtered` stores the map on `FilteredChunks`, the ingest queue copies it onto the `Session`, and `setup_defense` copies it onto the `Defense`.
A chunk's chapter is the chapter of its `page_start`; pages before Chapter 1 are chapter 0.

## 2. D2 - the filter

`backend/chapter_filter.py` holds pure functions (`is_opening`, `target_chapter`, `off_chapter`) and `ChapterRetriever`, which wraps the M9-routed retriever:

- A domain panelist with no earlier turn gets every off-chapter chunk added to `exclude_indices`; near-tie sampling runs unchanged over what's left.
- Target chapter = `min(HOME_CHAPTER[key], last detected chapter)`, read from `opening_order.py`, the single source.
- Routing runs inside the wrapper, so its blocks always apply; the filter only narrows.
- If nothing is left, the wrapper retrieves again without the chapter exclusion, with routing and the usual exclusions intact.
- Follow-ups and the Devil's Advocate don't retrieve, and a panelist's later turns aren't openers, so none of them is touched.
- With no chapter map, or the flag off, `_opening_filter` returns `None` and `_next_question` passes the routed retriever exactly as M12 did.

v1's engine calls the retriever once per new topic (`engine.py:387`) and never for a follow-up, so no v1 change was needed.
`git diff main -- academic_defense_simulator/` is empty.

## 7. D5 - the Neon idle connection

`backend/quota.py`: `ConnectionPool(min_size=0, ...)`, `max_size` unchanged.
`PostgresQuotaStore` takes `max_idle_s` (default 600, the library default) so a test can shorten the idle window.

psycopg_pool 3.3.3 accepts it:

```
3.3.3 accepts min_size=0: 0 3
```

The old setting next to the new one, against a port where nothing listens, 1.5 s after `open()`:

```
min_size=1: pool_size=1 connections_num=1 connections_errors=0
min_size=0: pool_size=0 connections_num=0 connections_errors=0
```

With `min_size=1` the pool connects in the background as soon as it opens; with `min_size=0` it makes no connection until a quota call needs one.
