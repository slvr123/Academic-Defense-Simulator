## 1. The backend

### The key's path

1. `POST /keys/check` reads the key from `X-Gemini-Key` and runs v1's `validate_gemini_key`, which makes one `client.models.list()` call and no generation.
   It answers `{"ok": true}`, or 400 with code `invalid_key` and the doc's copy.
   A missing or blank header is the same 400.
2. `POST /sessions` reads the same header before the body.
   With a key, it runs the same check again (400 `invalid_key` on a refusal, and no session is made), skips the free-quota pre-check, and passes the key to `SessionStore.create`.
3. The key lives on `Session.gemini_key`, a `SecretStr` with `repr=False`.
   `SessionStore._dropped` sets it to `None`, so End session and expiry both drop it; a restart loses it with the rest of memory.
4. `/start` builds the defense's providers with `providers_factory(calls, session.gemini_key)`.
   `ProvidersFactory` is now a `Protocol` whose second argument is the own key; `None` builds on the server's key exactly as before.

`backend/own_key.py` holds the header name, the three messages, the error mapping and the suggestions wrapper.
It reads Gemini's errors by shape (an exception in the cause chain with an int `code` and a str `status`), so `google.genai` is still imported only by v1's provider.

### The quota (Decision 2)

```python
# backend/defense_routes.py, /start
if session.gemini_key is None:
    session.charge = reserve_quota(client_ip(request, settings.trusted_proxy_hops))
else:
    logger.info("own-key start session=%s, no quota reserved", session_id)
```

`reserve_quota` is where both the per-IP limit and `quota.reserve` happen, so an own-key start takes neither.
With no charge on the session, End session and expiry have nothing to refund.

### Errors mid-defense (Decision 4)

`llm_failure(exc, own_key=...)` tries `own_key_failure` first on an own-key defense:

| Gemini's answer (after v1's retry) | Own key | Server key (unchanged) |
|---|---|---|
| 429 (`LLMQuotaExhaustedError`) | 429 `own_key_limited`, `Retry-After: 60` | 503 `panel_busy` |
| 401, 403, or 400 `INVALID_ARGUMENT` naming the API key | 403 `own_key_rejected` | 502 |
| 503 (`LLMServiceUnavailableError`) | 503 `panel_busy` | 503 `panel_busy` |
| anything else | 502 | 502 |

Nothing is recorded on any of them, so the same answer can be sent again.

**Flag:** the status codes are mine; the doc names only the codes.
I picked 400 for `invalid_key`, 403 for `own_key_rejected` and 429 for `own_key_limited`, and the frontend branches on the code, not the status.

### The suggestions wrapper (Decision 3)

For own-key defenses only, `gemini_providers_factory` wraps suggestions in `SuggestionsWithFallback(primary=2.5-flash, fallback=3.1-flash-lite)`.
When the primary raises and the Gemini error behind it is a 403, a 404 or a 429, it logs one line and runs the same call on the fallback, once.
The 429 is amendment 2 (section 13): Google often reports a free-tier block on a model as a 429 with a limit of 0.
Anything else re-raises, and so does a failed fallback, so a 503 or a second failure reaches v1's report builder as before, and v1 ships the debrief without suggestions.
The log line is the reason only: `suggestions fallback to=gemini-3.1-flash-lite reason=404 NOT_FOUND`.

## 3. Frontend

- **The control.** "Use your own Gemini key" sits in the header next to the quota line, collapsed (`aria-expanded="false"`).
  Opening it shows the password input, "Use this key" and the help line, linked to `https://aistudio.google.com/apikey`.
  When `/quota` says 0 left, the panel is open on its own above the start screen with "Today's free defenses are used. Use your own free Gemini key to keep practicing.", and the header toggle goes away.
- **The quota line** reads "Using your own key" once Google has accepted the key, and Upload and the sample button are no longer blocked by the free count.
- **Where the key lives.** In the input's state until Google accepts it, then in a `useRef` in `useFlow`, never in reducer state, storage or the URL.
  It goes in the `X-Gemini-Key` header of `/keys/check` and of the upload (`xhr.setRequestHeader`), never in the form.
- **Errors.** The three codes map to a new `ApiError` kind, `ownKey`, which shows the server's copy as a notice.
  The answer stays in the box, so after `own_key_limited` the same answer can be sent again.
- **How it works** is a section below the two columns on the start screen, reached by a header link that scrolls to it without touching the URL.
  Neither renders outside the start screen.

**Flag: when the key is dropped.** The doc says the key is "sent once (Decision 2) and then dropped from page state".
I drop it as soon as an upload makes a session with it, or when Google refuses it.
On any other upload failure (network, busy, too large) the page keeps it, so "Try again" resends it.
Dropping it there would make that retry go out without a key, which quietly spends a free defense.
"Remove key" drops it by hand, and so do End session and starting over.

**Flag: a refresh mid-defense.** The server half holds: the key is on the session, so the session keeps working.
But the v2 frontend has never resumed a defense after a refresh (nothing in it stores the session id), so a refreshed page shows the start screen.
That's unchanged by M17.

## 6. "How it works": every claim and its evidence

The copy as shipped (`frontend/src/components/HowItWorks.tsx`):

> **RAG, turned around.** Instead of searching your paper to answer your questions, the panel searches it to question *you*. Each panelist looks for something worth challenging (a claim, a number, a decision) and asks about it. After you answer, you see the exact passage and page it came from.
>
> **A panel, not a chatbot.** Each panelist has a lane, such as problem and objectives, methodology, or results. Each opens in its own chapter when your PDF's chapter headings can be read, so the first round walks forward through your paper. A Terror Panelist speaks last and goes after your earlier answers.
>
> **It adapts, quietly.** Every answer is scored against a rubric you don't see, and weak answers draw follow-ups. Scores appear only in the debrief, with suggestions grounded in the same passages.
>
> **Measured, not guessed.** Early panelists asked students about other authors' studies cited in their literature review, as if that work were theirs. That was measured, independently judged, and fixed by keeping those passages away from the panel. A chapter filter took opening rounds that walk forward through the paper from 5 of 10 to 10 of 10 on our eval.
>
> Built by Sean Silver Allata with FastAPI, React and Gemini, with retrieval in plain numpy. [Source on GitHub](https://github.com/slvr123/Academic-Defense-Simulator)
