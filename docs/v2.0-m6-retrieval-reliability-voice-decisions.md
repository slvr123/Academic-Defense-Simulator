### Slice 1 — retrieval follow-up

#### H1. The reference-list filter
**The defect (M5 finding):** with the contents page gone, the bibliography on sample3 (pp. 80–81) became the best match for Statistical Analysis and Results & Conclusions. A reference list is a list of paper titles touching every topic in the field, so it attracts generic focus queries the same way a contents page did.

**Rule.** In `backend/page_filter.py`:
- **Start:** the first line *after the front-matter boundary* that consists only of a references heading: `References`, `Bibliography`, `Literature Cited` or `Works Cited`, any case, optionally numbered. A line that also carries a page number or dotted leaders is not a heading.
- **Accept the start only if it falls in the last half of the document's pages.** Otherwise filter nothing (fail-open). That guards against a chapter that happens to be titled "Literature".
- **End:** the first later line that is only an `Appendix`/`Appendices`/`Curriculum Vitae`/`Glossary` heading (optionally lettered or numbered), or the end of the document.
- **Removed:** text from the start heading up to, but not including, the end heading. On the start page, the text *above* the heading stays, so the end of Chapter 5 isn't lost. On the end page, the text from the end heading onward stays. Appendices stay.
- **The trim happens on page text before v1's paragraph splitter runs.** Page numbers stay true to the PDF. The scanned check still counts all text. No-filter parity with v1 still holds.
- When no references heading is found → nothing removed.

*Downside I accept:* a document that titles its references differently isn't filtered.

#### H2. Pre-committed success rule for H1
Run M4's eval before (M5's chunker) and after (M5 + H1), on both documents. H1 passes only if all of these hold:
1. Zero archetype top-1 picks and zero simulated-session turns on removed reference text.
2. Removed ranges are listed per document, and nothing outside [references heading, end heading) is removed.
3. Navigation-page picks stay at 0. Check A doesn't move to a worse branch. Max displacement stays at 5 or below.

**If H1 fails:** revert H1 on the branch, record why, and continue with slices 2 and 3. H1 goes back to design in chat.
**References not detected on a document:** report "filter not applied" for that document; that's not a pass.

#### H3. The near-tie decision, pre-committed
After H1 (or after its revert), take the pooled near-tie rate from the final eval.
- **Above 50%:** adopt **seeded near-tie sampling.** A new-topic turn picks at random, but only among non-excluded chunks scoring within 0.02 of the best. Chunks outside that band can never be picked, so relevance costs nothing by construction. The random generator is seeded from `(session_id, turn number)`, so any session can be replayed exactly.
- **50% or below:** keep `top_k=1`, change nothing, and record the rate.

The eval's Check E gains a seeded replay mode so it stays reproducible.

**The one permitted edit to `academic_defense_simulator/`:** if sampling is adopted and the engine can't use it without a change, add one optional parameter (an injectable retriever) whose default reproduces today's behaviour exactly. v1's tests must pass unchanged, and a parity test must show v1 output is identical with the default. Any other change to v1 code → stop.
*Downside I accept:* sessions on the same document no longer retrieve identically. That's the point (it reduces cross-session repetition), but evals now measure distributions instead of single answers.

### Slice 2 — reliability (from M3/M3b open items)

#### H4. A lost `/start` response replays
A resent `POST /start` on a defense that has started but has no answers yet returns the open first question, the same body as the original, with status 200. No Gemini call, and no second slot reserved. A defense with answers → 409 with `code: "already_started"`. This supersedes M3's D16 "swallow 409" for `/start`.

#### H5. A way back from `stale_question`
Add `GET /sessions/{id}/current`, returning the open question (or `done`) and its turn number. When the client gets `stale_question`, it calls this endpoint, moves to the current question, and keeps the user's typed text in the box with a notice: "This answer was for an earlier question. You're now on question N." No reload needed.

#### H6. The per-IP limit is carried in the response
The `per_ip_limit` 429 body gains `limit: int`, and the frontend copy uses it instead of the hardcoded "3".

#### H7. Test timeouts
The App-level vitest files get a 15 s per-test timeout; everything else keeps the defaults. The backend sweep test's deadline becomes 15 s. Find out why one timeout cascades through a file, and fix the cause if it's in our test setup. **No automatic retries:** a test that fails must still fail.

### Slice 3 — voice latency

#### H8. Measure first
M3b measured 10–25 s per clip (about 21 typical) on real 40–80-word questions. Measure on real question texts from the M3/M3b live runs. For each text, record latency for the whole question and **time to the first sentence's audio** when split. Also log server-side `/tts` timing (`ms`, `chars`, `part`; never the text) so production timings show up in Render's logs from any real defense.

#### H9. Sentence-split playback, behind a flag
- `POST /tts` gains an optional `part` index. The server splits the question with a deterministic sentence splitter (in a pure function, with tests), synthesizes only that sentence, and returns it with an `X-TTS-Parts` header. Without `part`, the behaviour is unchanged.
- The client requests part 0, plays it, and fetches part n+1 while part n plays.
- Abuse limits become per part: at most 2 synth calls per part, and at most 8 parts per question.
- **Controlled by `ADS_TTS_SPLIT_SENTENCES`, default off.** Turning it on is my decision after the by-ear check (H10), done by setting an env var on Render. No new deploy needed.

#### H10. Pre-committed voice rule
VoiceDesign creates the voice from a description on each call, so separately synthesized sentences might not sound like the same person. Code saves, for 3 archetypes, the same question synthesized both whole and split, to a gitignored `voice-check/split/` folder for my listening.
- **Median time-to-first-audio ≤ 8 s, and I judge the split voices consistent →** I turn the flag on.
- **Median above 8 s →** record it, and leave the flag off whatever the listening says.
- **I judge the voices inconsistent →** leave it off. Voice latency goes back to design (options: a shorter spoken form, or starting synthesis as soon as `/answers` returns the next question).

v1's voice map and voice-design strings are unchanged (M3b E12).
