## Decision 1 — New field, additive only, no schema_version bump (LOCKED)

```python
class AnswerSuggestion(BaseModel):
    turn_index: int
    suggestion: str             # specific: what a stronger answer would have included
    grounding_reference: str    # cites back to the actual retrieved chunk — same
                                 # discipline the panelist prompts already enforce

class DefenseReport(BaseModel):
    # ...existing fields unchanged...
    answer_suggestions: list[AnswerSuggestion] = Field(default_factory=list)
    suggestions_fallback_used: bool = False
```

Both new fields have defaults, so existing persisted files (Sean's three real completed sessions, generated before this feature existed) parse unchanged under `PersistedSession`'s `schema_version: 1` — no migration, no version bump. They simply carry an empty `answer_suggestions` list, correctly reflecting that they predate the feature. No backfill.

## Decision 2 — New call: `gemini-2.5-flash`, fed the real transcript, one call per session (LOCKED)

**Model: `gemini-2.5-flash`.** This is a judgment task — deciding what a stronger answer would specifically have included, grounded correctly — same class Day 4 found flash-lite unfit for. Same reasoning applied consistently to the gate and to gap-clustering; applied here too.

**Input:** the full transcript — every turn's question, answer, `grounding_reference`, and `chunk_text` — in one call, not per-turn. Output: `list[AnswerSuggestion]`, one per turn.

**Fail-open**, same pattern as the relevance gate: on any API error, `suggestions_fallback_used = True`, report renders "Suggestions unavailable this session" in that section — narrative and everything else render normally, unaffected.

**New, independent prompt version:**

```python
ANSWER_SUGGESTIONS_PROMPT_VERSION = 1
```

Three now-independent version counters exist in this project: `PROMPT_VERSION` (session-generation: panelist/follow-up/scoring), `ANALYTICS_PROMPT_VERSION` (cross-session gap clustering, v1.0b), `ANSWER_SUGGESTIONS_PROMPT_VERSION` (this). Deliberate — each tracks a template that can evolve independently without falsely invalidating or conflating the others.

Directly answering the "too long" objection raised in chat: suggestions render as **one new section** — turn number + suggestion text, nothing else repeated. It sits alongside the existing pushback table, same visual weight, not nested inside each panelist card. Net report growth: one short section, not a per-turn expansion.

## Decision 4 — Capacity tradeoff: accepted plainly, no mitigation built (LOCKED)

`gemini-2.5-flash` calls/session go from 1 (gate only) to **2** (gate + suggestions). Free-tier ceiling (~20 RPD) now supports **~10 full sessions/day**, not ~20. No optional/best-effort lever, no per-day suggestion-skipping logic — accepted as-is, same documentation style as the standing flash-lite-scoring tradeoff. If this ever actually bites (a demo day pushing past ~10 sessions), it's revisited then, not preemptively engineered around now.

## Amendment — `build_report` two-provider signature (2026-07-23)

Not specified in the brief above, flagging per convention rather than absorbing it
silently. `build_report(session, provider)` became
`build_report(session, narrative_provider, suggestions_provider)`.

**Why:** Decision 2 pins the suggestions call to `gemini-2.5-flash` regardless of
`GEMINI_MODEL`, while the existing narrative call (v0.3c) must keep resolving
whatever `GEMINI_MODEL` is set to (flash-lite in dev). One `LLMProvider` instance
is bound to one model at construction time (see `GeminiProvider.__init__`), so a
single shared provider can't serve both calls under two different model pins. The
existing relevance gate already solved the identical problem the same way
(`_new_provider` vs `_new_relevance_provider`, two separately-constructed,
separately-pinned providers) — this reuses that pattern rather than inventing a
new one.

**Call sites updated:** `streamlit_app.py`'s session-completion driver (now passes
`_new_provider(...)` and the new `_new_suggestions_provider()`), and `main.py`'s
CLI driver (now constructs a second `GeminiProvider` pinned to `gemini-2.5-flash`
alongside the existing one). Existing `test_report.py` narrative tests updated to
pass a stub suggestions provider so they keep testing narrative behavior only.
