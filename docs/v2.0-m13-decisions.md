## Decision 0: The light theme becomes Red Pen (do this first)

Sean chose this palette on 2026-11-03 from a side-by-side of four candidates. It replaces the M12 Paper **values**. The theme keeps its internal name `paper`, so the stored theme choice in `localStorage`, the tests and the `[data-theme]` selector don't change. Chamber (dark) is unchanged.

**The concept:** your thesis being marked up. Black ink is used for everything the **user** operates. Red is used only for the **panel**.

| Token role | Hex |
|---|---|
| page background | `#F5F4F1` |
| surface (cards, question, panel cards) | `#FFFFFF` |
| border | `#DAD8D3` |
| Devil's Advocate dashed border | `#C4C1BA` |
| primary text | `#161616` |
| muted text | `#625E58` |
| **ink**: primary buttons, selected pills, the selected preset, the selected difficulty, links, upload icon | `#1C1C1C` |
| text on ink | `#FFFFFF` |
| **panel red**: speaking card border and "Speaking" label, the active transcript block's border, any pushback or follow-up marker | `#A8201A` |
| **passage highlight**: a fill behind the cited text, not an underline | `#F6DCD9` |

**Rules:**
- **Red is never used** on buttons, selected states, links or anything the user clicks. If an element currently uses the accent and isn't the panel speaking or citing, it becomes ink.
- **Selected but not filled** states, like the chosen defense-type pill or the chosen preset card, use an ink border and a faint neutral fill. They are never red.
- **Focus rings** stay functional and use ink.
- **Contrast, checked 2026-11-03:**
  - text on page background: 16.45
  - text on the highlight: 13.92
  - red on page background: 6.61
  - red on the highlight: 5.6
  - muted text on surface: 6.44
  - white on ink: 17.04

  Rerun the contrast script over every required pair and show the output. Derive hover and pressed shades from ink and check them too.
- **Favicon:** redraw it in panel red (`#A8201A`). It's currently oxblood.
- **Screenshots, the GIF and the share image** in Decisions 4 and 5 use this light theme. Where this doc says "Paper", it means these values.

**Audit as M12 did.** Grep for any accent use that bypasses the tokens. Report each element that moved from accent to ink, so Sean can see the role split was applied, not guessed.

## Decision 6: Record what we learned about the pinger

Add a short **Operations** section to `docs/ROADMAP.md`, without changing any milestone content. It records facts only:

- **Backend:** Render free tier. It spins down after 15 idle minutes and takes about a minute to wake.
- **Pinger:** cron-job.org hits `/status` every 10 minutes, 06:00–23:59 Asia/Singapore. That's about 558 of the 750 free hours a month.
- **Observation, 2026-11-03:**
  - M14 went live at 13:33.
  - Pings at 13:50, 14:00 and 14:10 got `503` in about 1 s.
  - A browser visit at about 14:13 woke the service.
  - Every ping from 14:20 on returned `200`.
- **Working conclusion, still to be confirmed by the 2026-11-04 06:00–06:30 runs:** the pinger keeps an awake service awake, but may not wake a sleeping one. The first real visit does that, through the frontend's pre-wake call.
- **Neon:** the quota pool holds no idle connection (`min_size=0`, M14), so nothing reconnects in the background.
- **The `test_quota_db.py` real-database run** (10 passed, 0 skipped) and the M14 pool tests. If section 7 of `v2.0-m14-results.md` still records them as skipped, rerun them, update that section with the real output, and commit.
