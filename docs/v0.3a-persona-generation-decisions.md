## Decision 1 — Panel composition: rule-based, priority-ordered lists

Deterministic mapping from `(defense_type, other_subtype)` to a priority-ordered
archetype list, truncated to `profile.panel_size`. Zero LLM calls, pure function,
unit-testable. LLM-selected composition rejected: adds a call and a failure mode for
no demonstrated benefit.

```python
# academic_defense_simulator/panel.py

PANEL_COMPOSITION: dict[str, list[str]] = {
    "thesis": [
        "methodology_expert",
        "literature_theory_specialist",
        "ethics_practicality_reviewer",
        "technical_implementation_reviewer",
    ],
    "capstone": [
        "technical_implementation_reviewer",
        "methodology_expert",
        "ethics_practicality_reviewer",
        "literature_theory_specialist",
    ],
    "other/oral_comps": [
        "literature_theory_specialist",
        "methodology_expert",
        "ethics_practicality_reviewer",
    ],
    "other/scholarship_panel": [
        "ethics_practicality_reviewer",
        "methodology_expert",
        "literature_theory_specialist",
    ],
    "other/grant_defense": [
        "ethics_practicality_reviewer",
        "methodology_expert",
        "literature_theory_specialist",
    ],
    "other/certification_interview": [
        "technical_implementation_reviewer",
        "methodology_expert",
        "ethics_practicality_reviewer",
    ],
}

def compose_panel(profile: DefenseProfile) -> list[str]:
    """Return archetype keys for this profile, truncated to panel_size.
    Pure function, no LLM. Key format: defense_type, or
    'other/{other_subtype}' when defense_type is OTHER.
    Raises ValueError if panel_size exceeds the composition list length —
    the UI caps the selector so this never fires from the form (see below)."""
```

**Ordering rationale:** lead with the archetype whose lane matches what that defense
format interrogates first — capstones get grilled on what was built; theses on
whether the method answers the question; grant/scholarship panels on practicality
and impact; oral comps on theoretical grounding.

- Devil's Advocate absent from every list — orchestration feature, 0.3b.
- **Underfilled panel is an explicit error, not a silent truncation-in-reverse**
  (revised from the draft's silent-full-list behavior, per Sean 2026-07-09).
  If `panel_size` exceeds the composition list length (only possible for
  `other/*` subtypes at panel_size 4–5), `compose_panel` raises `ValueError`
  with a message naming the subtype and its maximum panel size. Rationale: a
  session that quietly runs a smaller panel than the profile requested is the
  same class of defect as a transcript with a silently skipped question — the
  artifact no longer matches what was asked for.
- **The UI prevents the error from ever firing:** when `panel_size` becomes a
  form control in this session, the Streamlit form caps the selector's maximum
  at `len(PANEL_COMPOSITION[key])` for the currently selected defense
  type/subtype. The `ValueError` is a guard for programmatic/test callers, not
  a user-facing failure path. Belt (UI cap) and suspenders (raise), both cheap.

## Decision 2 — Persona flavor: one upfront structured-output call, whole panel

One LLM call per session generates all N personas in a single structured output,
cached on the session. Rejected: static-only pool (makes the pitch differentiator a
lookup table), per-panelist calls (multiplies calls for nothing).

### New models

```python
# academic_defense_simulator/models.py (alongside existing models)

class Panelist(BaseModel):
    archetype_key: str          # key into ARCHETYPE_CONFIG
    panelist_name: str          # surname only — template supplies "Dr.", per Day 2's double-Dr. fix
    persona_framing: str        # 1–2 sentence character framing, injected into prompts (Decision 3)

class PanelGeneration(BaseModel):
    """Structured output schema for the persona-generation call."""
    panelists: list[Panelist]
```

### Persona-generation prompt

Lives in the prompts module with the other templates.

```python
PERSONA_GENERATION_PROMPT = """You are configuring an academic defense panel simulation.

Defense type: {defense_type}{other_subtype_line}
Domain: {domain}
Topic: {topic}

Generate one distinct panelist persona for each of the following archetype roles, in order:
{archetype_roster}

For each panelist provide:
- "archetype_key": the exact role key given above, unchanged
- "panelist_name": a realistic surname only (no title, no first name) — vary cultural origin across the panel; do not reuse a surname
- "persona_framing": 1–2 sentences of professional character — their academic background flavor, questioning temperament, and what they are known to press candidates on, calibrated to the domain and topic above. Write it in second person ("You are known for..."), as it will be injected into that panelist's system prompt.

Respond ONLY with JSON matching this schema, no other text:
{{
  "panelists": [
    {{"archetype_key": "...", "panelist_name": "...", "persona_framing": "..."}}
  ]
}}
"""
```

`{archetype_roster}` renders as one line per archetype:
`- {archetype_key}: {archetype_title} — {archetype_focus}` from the existing
`ARCHETYPE_CONFIG`.

### Post-parse validation (Python, not model trust)

- Every `archetype_key` in the output must exist in `ARCHETYPE_CONFIG` and match
  the requested roster exactly (same keys, same count). Order mismatch: reorder in
  Python to roster order — don't fail.
- Any violation (missing/extra/unknown key, duplicate surname) counts as a
  malformed response → the retry/fallback path below.

### Failure behavior — deliberate departure from 5a's fail-clean rule

**Retry once, then fall back to the static pool with generic framing.** Locked by
Sean with the departure explicitly acknowledged: 5a's fail-session rule protected
transcript integrity (a skipped question or score corrupts the defense record); a
generic persona degrades aesthetics only. Failing a whole session over garnish is
the wrong trade.

```python
FALLBACK_PANELISTS: dict[str, Panelist] = {
    "methodology_expert": Panelist(
        archetype_key="methodology_expert",
        panelist_name="Reyes",
        persona_framing="You are a rigorous methodologist known for pressing candidates on whether their chosen approach actually answers their stated research question.",
    ),
    "literature_theory_specialist": Panelist(
        archetype_key="literature_theory_specialist",
        panelist_name="Okafor",
        persona_framing="You are a widely read theorist known for pressing candidates on gaps between their claims and the literature they cite.",
    ),
    "technical_implementation_reviewer": Panelist(
        archetype_key="technical_implementation_reviewer",
        panelist_name="Tanaka",
        persona_framing="You are a hands-on builder known for pressing candidates on whether the implementation matches what was claimed and why each tool was chosen.",
    ),
    "ethics_practicality_reviewer": Panelist(
        archetype_key="ethics_practicality_reviewer",
        panelist_name="Alvarez",
        persona_framing="You are a pragmatic reviewer known for pressing candidates on real-world applicability, limitations, and the implications of deploying their work.",
    ),
}
```

Fallback use is logged (`logging.warning`) and recorded in the transcript export
(see Evidence section) so an eval run always knows whether it exercised generated
or fallback personas.

- "Reyes" deliberately kept as the methodology fallback — continuity with every
  eval artifact from Day 2 onward.

## Decision 3 — `persona_framing` is injected into the question prompts

**`PROMPT_VERSION` bumps `"0.2"` → `"0.3"` in this session.** UI-only framing was
rejected: it would make the personas dynamic in name only, not behavior. Pattern 2
re-renders persona framing fresh on every call — this is exactly the field that
mechanism exists to carry.

Template change, both paths, one new line each:

```
You are Dr. {panelist_name}, the {archetype_title} on a {defense_type} defense panel.
{persona_framing}

Your focus: {archetype_focus}
...
```

- Applies to **both** `PANELIST_SYSTEM_PROMPT` and `FOLLOWUP_SYSTEM_PROMPT` —
  identical placement, so the persona holds character on both paths.
- `SCORING_SYSTEM_PROMPT` is **unchanged**. Scoring is a judgment task; injecting
  character flavor into the judge adds a variable to the rubric that Day 4/5
  verified without it. The version bump still covers it (one constant for the set),
  but the wording diff for scoring is zero — state this in the Code session's
  verification notes.
- **Re-verification obligation:** Day 4's own rule — wording changes silently
  invalidate earlier verification. The v0.2.5 probe machinery
  (`scripts/probe_question_gen.py` + `is_grounded()`) exists for exactly this.
  The 0.3a Code session re-runs the probe against the new templates: minimum 4
  new-topic + 2 follow-up questions, same DAZSMA doc, results appended to a new
  JSONL (`probe_question_gen_v0.3_results.jsonl` — don't overwrite the v0.2 file;
  it's the irreplaceable human-judged record). Grounding tally broken out by path,
  same as before. Difficulty levels probed: 2 and 3 only — difficulty 4 stays
  parked for 0.3b per the standing flag; don't burn probe calls re-confirming a
  known finding mid-session.

## Decision 4 — Domain/topic auto-extraction at ingestion

One LLM call at ingestion prefills the `domain`/`topic` form fields. User-editable,
never silently overriding — the user's final form values are what enter
`DefenseProfile`, whether edited or not.

### Extraction input

First 3 chunks of the ingested document, concatenated, capped at ~3000 characters.
Title, abstract, and framing live at the front of any academic document; feeding
the whole doc costs tokens for no gain. No new retrieval logic — the chunk list
already exists at this point in the flow.

### Extraction prompt + schema

```python
class DocumentProfileExtraction(BaseModel):
    domain: str   # academic field/discipline, e.g. "Software Engineering"
    topic: str    # short research title/summary, <= 15 words

EXTRACTION_PROMPT = """The following is the opening excerpt of an academic research document.

\"\"\"
{document_head}
\"\"\"

Identify:
- "domain": the academic field or discipline this work belongs to (2–5 words)
- "topic": the research title or a faithful short summary of it (at most 15 words) — prefer the document's own title verbatim if present

Respond ONLY with JSON matching this schema, no other text:
{{"domain": "...", "topic": "..."}}
"""
```

### Failure behavior

Same aesthetic-degradation logic as Decision 2: retry once, then fall back to
**blank fields** — the user types them, exactly as in v0.2. Log a warning; never
block the session.

### UI flow reorder — named explicitly so Code doesn't treat it as creep

`streamlit_app.py` reorders to **upload → ingest → extract → profile form
(prefilled) → start session**. Currently form-then-upload. This is a thin
orchestration change in the Streamlit layer only; zero business-logic modules
change, the import boundary (standing constraint 4) holds.

**`panel_size` goes from hidden (5c) to a form control in this session** — it
now visibly does something (the generated panel lands in the export), and it
must be a control for the Decision 1 UI cap to exist. `difficulty_start`
remains hidden/hardcoded; nothing in 0.3a changes its role. Extraction runs once
per uploaded document, result cached in `st.session_state` keyed by
`document_id` — re-rendering the form must not re-call the LLM.

## Decision 5 — Slice boundary: generate the full panel, run panelist[0]

0.3a sessions generate and store the **full** panel but execute the defense with
only the first panelist in composition order. Turn-taking does not exist until
0.3b and is not improvised here.

### `DefenseSession` change

```python
class DefenseSession(BaseModel):
    profile: DefenseProfile
    panel: list[Panelist]              # NEW — full generated panel, composition order
    difficulty_current: int
    turns: list[ConversationTurn] = Field(default_factory=list)
    # used_chunk_indices property unchanged
```

- The active panelist is `session.panel[0]`. The loop's retrieval query remains the
  active panelist's `archetype_focus` (looked up via `archetype_key`) — unchanged
  mechanism, now sourced through the panel rather than a hardcoded archetype.
- `ConversationTurn` unchanged — per-turn panelist attribution is a 0.3b field,
  added when more than one panelist can actually speak.
- The full panel lands in the transcript export automatically
  (`model_dump_json()` picks it up) — that export **is** the slice's evidence:
  persona generation demonstrably working end-to-end without smuggling
  orchestration in early.

### Export addition

The export payload gains one flag alongside `prompt_version`:

```python
export_payload = {
    "prompt_version": PROMPT_VERSION,          # "0.3" after this session
    "personas_fallback_used": bool,            # True if Decision 2's fallback fired
    "session": json.loads(session.model_dump_json()),
}
```

Stamped at export time in `streamlit_app.py` only, same pattern as
`prompt_version` — `DefenseSession` carries the panel (it's session state), but
not the fallback flag (it's provenance metadata, same class as prompt_version).
The Streamlit layer tracks the flag in `st.session_state`.

## Call budget (standing constraint 2)

Per 0.3a session: **14 flash-lite calls** — 1 extraction + 1 persona generation +
12 turn calls (6 turns × question + score). Panel size multiplies nothing; only
the active panelist generates and scores. ~35 full sessions/day against the
500 RPD budget.

One-time session costs for the Code session itself: probe re-run ≈ 10–14 calls
(Decision 3's re-verification), plus fallback-path forcing (0 calls — forced via
mock/injected fault per the standing evidence bar, not by burning quota).
