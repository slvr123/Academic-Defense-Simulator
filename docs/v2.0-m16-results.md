## 2. The v1 change, as Decision 2 allows it

1. **One slot.** `{language_line}` sits right after `{other_subtype_line}` in `PANELIST_SYSTEM_PROMPT` (`- Defense type: {defense_type}{other_subtype_line}{language_line}`).
   `FOLLOWUP_SYSTEM_PROMPT` and `DEVILS_ADVOCATE_SYSTEM_PROMPT` have no `other_subtype_line`, so the slot goes at the end of the nearest equivalent line, the panelist's own brief: after `Your focus: {archetype_focus}` and after the Devil's Advocate's `Your role: ...` paragraph.
   Decision 2 assumed all three templates had the subtype slot; this is my reading of "where it sits" for the two that don't.
2. **One parameter.** `language_line: str = ""` on `_generate_question`, passed on to `_generate_da_question` and into every `.format` call, the same way `other_subtype_line` travels.

No other wording moved, and `PROMPT_VERSION` stays `1.2.2`.

With the slot empty, the golden test still passes against the changed v1:

```

```

## 3. STOP POINT A: two v1 tests format a template by hand

A `str.format` slot is required, not optional: any caller that formats a template without `language_line` gets a `KeyError`.
The engine is the only production caller, and it now passes the slot.
But two v1 tests in `tests/test_followup_framing.py` call `FOLLOWUP_SYSTEM_PROMPT.format(...)` directly, with every slot spelled out, and they now fail:

```
$ pytest backend/tests/test_m16_prompt_golden.py tests/test_followup_framing.py -q
E       KeyError: 'language_line'

tests\test_followup_framing.py:91: KeyError
FAILED tests/test_followup_framing.py::test_rendered_full_prompt_has_no_unfilled_placeholders_same_asker
FAILED tests/test_followup_framing.py::test_rendered_full_prompt_has_no_unfilled_placeholders_colleague
2 failed, 7 passed in 0.17s
```

Decision 2 says v1's suite must still pass with only the known single failure, and it allows no v1 change beyond the slot and the parameter.
So this is the stop point: keeping v1's suite green needs one more v1 change, and there's no way to make it with only those two items.

`scripts/inspect_rag.py` also formats `PANELIST_SYSTEM_PROMPT` by hand, but it's been missing `persona_framing` and other slots since v0.3, so it already raised `KeyError` before M16 and isn't covered by any test.
