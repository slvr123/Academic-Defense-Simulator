### The flag, the field and the threading

- `ADS_TAGLISH_MODE` (`taglish_mode`, default `false`) in `backend/settings.py`, reported by `/status` as `taglish_mode`.
- `PanelConfig.panel_language`: `"english"` (the default, also when the field is left out) or `"taglish"`. With the flag off, an upload asking for Taglish gets 422: "Taglish mode is off on this server, so the panel speaks English only."
- `setup_defense` reads it into `Defense.language`. `_next_question` passes `question_language_line(language)` into v1's `_generate_question`, and `_start_closing` passes the language into the closing prompt and the matching fixed line into the closing call.
- Scoring, the report, the answer suggestions, extraction and the personas get no language line.

### A harness bug I found, recorded for later

A backend test whose `TestClient` shuts down while an upload is still ingesting hangs forever in the app's lifespan shutdown.
My first diagnosis, "a refused upload followed by an accepted one", was wrong: a probe that seemed to pass had printed nothing, which meant it had hung.
The real trigger is ending the client mid-ingest, and it predates M16.
The pre-M16 test `test_api.py::test_valid_panel_is_stored` hangs 4 runs of 4 on its own, though it passes in the full suite:

```
run 1 rc=124
run 2 rc=124
run 3 rc=124
run 4 rc=124
```

A pair probe (an invalid panel, then a valid upload) also hung on the parent `2ef8885`: `parent exit=124`.
The hang is in app code, where cancelling the ingest worker mid-`asyncio.to_thread` never lets shutdown finish.
So it isn't a small test-only fix, and the conftest-level workaround (wait for ingest to drain on every exit) would hide what may be a real shutdown bug.
I recorded it in the ROADMAP as a known harness bug, and the new tests wait for every accepted upload to be ready.
