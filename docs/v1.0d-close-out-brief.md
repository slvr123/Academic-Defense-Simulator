# PHASE 1 — Investigation (read-only)

## Task 1 — Key-handling audit *(gating)*

The app is deployed and already accepting user-supplied Gemini keys. The
persistence layer landed **after** v0.4a's key-leak audit ran, so that audit no
longer covers the current write surface. The README will claim keys are never
logged and never persisted beyond the session; verify it or break it.

**Static trace.** Find where a user-supplied key enters the app and every path it
can reach. At minimum inspect `config.py`, `llm/gemini_provider.py` (every log
and exception path — an exception message that stringifies the request is a
leak), `persistence.py`, `demo_counter.py`, `analytics.py`, and whatever builds
the export payload.

**Empirical check, which is the part that actually counts.** Run a real session
(or construct and persist a `PersistedSession` through the normal code path) with
a sentinel key value — `AIzaSENTINEL_DO_NOT_SHIP` — then grep the entire
`sessions/` directory, any written log files, and the export payload for that
sentinel. A sentinel catches indirect paths a code read misses: serialization by
inclusion rather than by name, an exception that carries the request, a debug
line inside a dependency.

**Verify:** the grep command and its raw output, including the empty case. Empty
output *is* the evidence — but only if the sentinel demonstrably entered the run.
Show that too, or a clean grep only proves the test didn't work.

## Task 2 — Git history secret scan *(gating)*

A clean working tree says nothing about commit 40. Enabling GitHub secret
scanning protects future pushes; it does not retroactively unpublish anything.

- Any `.env` ever added: `git log --all --diff-filter=A --name-only | grep -iE '(^|/)\.env$'`
- Any Gemini key literal across all history: search full history for the `AIza`
  prefix pattern. The repo is small enough that a full `git log -p --all` scan is
  fine.
- Any other hardcoded credential pattern noticed along the way.

**Verify:** each command and its raw output, empty results included.
