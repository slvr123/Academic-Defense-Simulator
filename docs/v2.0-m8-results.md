### Slice 2 - voice cloning

**What changed.**
`backend/tts_clone.py` adds `ADS_TTS_VOICE_MODE` (`design`, the default, or `clone`).
In `design` mode the app uses v1's `synthesize_speech` itself, so today's request is unchanged byte for byte.
In `clone` mode `/tts` calls `mimo-v2.5-tts-voiceclone` with the asking archetype's reference clip as a data URI and an empty style instruction, so the voice comes from the clip alone.
Everything else about `/tts` is the same route: the limits, validation, logging without text, and the threadpool.
Clone mode refuses to start unless all 9 reference clips exist, and the backend logs `tts voice_mode=... split_sentences=...` at startup.

The 9 reference clips are in `backend/voice_refs/`, made with v1's VoiceDesign voices and descriptions unchanged, resampled to 16 kHz mono (2.16 MB in all, under the 3 MB cap).

**The bench** (`frontend/src/components/Bench.tsx`).
Every panelist sits in a row with v1's PNG portrait.
Only the active one is lit: amber top bar, a soft glow, a full-colour portrait and a highlighted name plate.

The Devil's Advocate's plate is dashed.

**The question.**
Newsreader at the mockup's 28 px (19 px on a phone), the "Grounded in a passage from your document - revealed after you answer" line, and the four steps Asking, Your answer, Reviewing, Handoff.
The steps follow the real phase: Asking while the question is still being written out or voiced, Your answer once it's ready for input, Reviewing while the answer is submitted.
On a phone the Submit button sits in a bar at the bottom of the screen.

**The source reveal.**
After an answer is recorded, the next question appears beside "What Dr. X was reading": the passage on a paper card, labelled "PDF page(s) N", with the question's `grounding_reference` highlighted, and "Answer recorded. Scores stay sealed until the debrief."
The backend finds the highlight (`backend/highlight.py`): it uses v1's `is_grounded` as the gate, so a reference only gets a highlight if the grounding check accepts it, then finds the span the same way v1's `grounding_ratio` searches.
The span goes out on `Source.highlight` as UTF-16 offsets, which is how JavaScript indexes strings.
`QuestionOut` and `TranscriptTurn` also gained `grounding_reference`, as K6 asked.
All three fields are additive.

**Scores stay sealed (K7).**
The per-answer score card is gone.
The evaluation still comes back from `/answers`, but nothing on the question screens shows it.

**The debrief (K8).**
It leads with the headline score: `overall_raw`, the mean of the three dimension averages, computed in Python (`backend/defense.py`, `overall_raw`) and rescaled on the client by `toHundred` like every other score.
Below it are the three averages and the scale caption, then the narrative, then one card per question, collapsed except the first: that turn's scores, my answer, the paper passage with the highlight, "The gap the panelist found" (`primary_gap`) and "A stronger answer" (the turn's suggestion).
The per-panelist and pushback sections and the full transcript stay.
`AnswerScore` and the rubric are untouched (`git diff main -- academic_defense_simulator/` is empty).

## 3. Concepts map

- **Design tokens in Tailwind's theme.**
  Each colour is named once as a CSS variable inside `@theme`, and Tailwind turns every `--color-x` into utilities like `bg-x` and `text-x`.
  Components only use the names, so changing the whole palette (as K6 did) is one file, and a contrast check can read the same file.
  `frontend/src/index.css:7`.
- **WCAG contrast ratios.**
  The ratio compares the relative luminance of text and background, from 1:1 (same colour) to 21:1 (black on white).
  AA asks 4.5:1 for body text and 3:1 for large text and for outlines you need to see; `scripts/check_contrast.py` computes it for every pair the theme uses.
  `scripts/check_contrast.py:67`.
- **`prefers-reduced-motion`.**
  It's an operating-system setting that a page can read with a media query, for people whom motion makes ill or distracts.
  Here every animation opts out with `motion-reduce:`, and one rule at the end of the stylesheet stops anything left.
  `frontend/src/index.css:129`.
- **CSS transitions vs keyframes.**
  A transition animates between two values when a property changes, like the bench light fading from one seat to the next when `active` changes.
  A keyframe animation runs a sequence on its own, once or on a loop, like the breathing ring or the reveal sliding in.
  `frontend/src/components/Bench.tsx:20` (transition), `frontend/src/index.css:81` (keyframes).
- **Voice cloning vs voice design.**
  Voice design invents a voice from a text description on every call, so two calls with the same description can sound like two people.
  Voice cloning copies the voice in a recording you send with each call, so every call sounds like that recording.
  `backend/tts_clone.py:52`.
- **Why a headline score is computed in the backend.**
  A number shown as the result of a defense should have one owner that's tested, not a formula repeated in each client.
  The backend computes the mean on v1's 1-5 scale and the client only rescales it for display, as it does for every score.
  `backend/defense.py:275`.
- **Highlighting a fuzzy match in React.**
  React can't wrap part of a string in `<mark>` by searching the rendered page; the text has to be cut into before, marked and after, and rendered as three pieces.
  The backend finds the span with v1's fuzzy match and sends offsets in JavaScript's units, so the client only slices and never guesses.
  `frontend/src/lib/highlight.ts:10`, `frontend/src/components/Sources.tsx:22`, `backend/highlight.py:64`.
