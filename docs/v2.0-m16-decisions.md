## The goal

Filipino thesis panels code-switch, and this mode lets the panel do the same. **Taglish only, no pure Tagalog.** Taglish is how real panels talk, and it's easier to make sound natural.

## Decision 1: Scope

| Part of the app | In Taglish mode |
|---|---|
| panelists' questions, follow-ups, the Terror Panelist's challenges | **Taglish** |
| closing lines (M15) | **Taglish** |
| the candidate's answers | whatever language they choose: English, Taglish or Tagalog |
| scoring (AnswerScore and the rubric) | **unchanged**; see Decision 4 |
| the debrief report and answer suggestions | **English** (easier to share) |
| interface text: buttons, labels, the start screen | **English** |
| retrieval, routing, chapter filter | **unchanged.** Queries and the paper stay English, so nothing upstream of generation moves |

## Decision 2: The v1 exception, as narrow as it can be

Sean approved one scoped exception to "v1 stays untouched". It's needed because the question prompts live in v1.

**Allowed:**
1. **One new optional slot**, `{language_line}`, added to `PANELIST_SYSTEM_PROMPT`, `FOLLOWUP_SYSTEM_PROMPT` and `DEVILS_ADVOCATE_SYSTEM_PROMPT`. Place it where `other_subtype_line` sits.
2. **One new optional parameter**, `language_line: str = ""`, threaded through the engine's question generators the same way `other_subtype_line` is, so callers that don't pass it get today's behavior.

**Not allowed:**
- any change to existing prompt wording;
- any change to AnswerScore, the rubric, the scoring prompt, the report prompts or the answer-suggestion prompts;
- any other v1 change.

**The byte-identical gate.** Before any other M16 work, add a golden test. Render every changed prompt with `language_line=""` for fixed inputs, and assert the output is **byte-for-byte identical** to the pre-M16 rendering, captured from the parent commit. The v1 Streamlit app must still pass its suite, with only the known single failure.

**STOP POINT A:** the exception turns out to need anything beyond these two items.

## Decision 3: The language line (drafted here; Code may adjust the wording and must quote the final text)

> Speak in Taglish: the natural, conversational mix of Filipino and English that Filipino thesis and capstone panels actually use. Keep technical terms, the paper's own terms, statistical terms, numbers and citations in English. Don't translate or paraphrase quotes from the excerpt; quote them as written. Use respectful register (po and opo are fine but not in every sentence). Don't use deep or formal Tagalog that a panel wouldn't say aloud. Your output field names and format stay exactly as instructed above.

- The closing-line prompt from M15 takes the **same line**. It's on the v2 side, so no exception is needed there.
- **English mode passes an empty string**, so English sessions stay identical.

## Decision 4: Is scoring fair to Taglish answers?

The real risk is that the scorer, with an English rubric, quietly marks Taglish answers lower. **The rule is written before the data.**

- **Pairs:** 10 answers to real AniCheck questions, each written twice with **identical content**, once in English and once in natural Taglish.
  - Claude (in Code) writes them.
  - Sean checks 3 pairs for fidelity in chat afterwards. That check isn't a merge gate.
  - Mix the strength: about 3 strong, 4 mid and 3 weak.
- **Scoring:** score every version **3 times** with the real scorer, at its real settings, and take the mean. Also report the spread within each version, to show the scorer's own noise.
- **Rule:**
  - **Pass:** the mean signed difference (Taglish minus English, across the 10 pairs) is within **±0.75 points of 15**, **and** no single pair differs by more than **2.0 points.**
  - **Fail: STOP POINT B.** Don't change the scoring prompt. A fix there would be a second exception, and Sean decides it in chat, with the numbers in front of him.
- **Spend, pre-authorized:** about 60 scoring calls plus generation for the questions, on the configured models.

## Decision 5: Does it sound natural?

Generate **15 Taglish panel lines** on AniCheck, using the thesis preset:
- 6 opening questions;
- 4 follow-ups;
- 2 Terror Panelist challenges;
- 3 closing lines.

List them verbatim in the results doc.

**Sean is the judge.** He rates each line in chat as natural, stiff or wrong. Code doesn't self-grade naturalness. The merge doesn't wait on this, but the flag default does (Decision 6).

## Decision 6: Setting, UI and flag

- **Start screen:** a "Panel language" choice of **English** (default) or **Taglish**, next to the defense profile. The recorded demo stays English.
- **State:** the choice travels with the panel configuration (a new optional field in the start request, defaulting to English) and is shown in the session header next to the defense type, e.g. "Thesis defense · Taglish".
- **Voice:** text-to-speech in Taglish is unproven.
  - With Taglish on, voice stays available but is labeled "voice may mispronounce Filipino".
  - Measure nothing beyond a single smoke test.
- **Flag:** `ADS_TAGLISH_MODE`, a boolean.
  - When off, the choice is hidden.
  - **It ships off.** Sean turns it on, with no deploy, after he has rated Decision 5 in chat and is happy with it.
  - That keeps a half-natural Taglish mode from going live by accident.
