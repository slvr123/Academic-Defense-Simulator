## 1. What changed, and the evidence

**In plain language.**
The backend now drops tables of contents and lists of figures, tables and appendices from a PDF before cutting it into passages, as long as they come before Chapter 1.
No panelist can be handed a contents page as evidence any more, on either test document.
On sample3, where 6 of the 8 archetypes used to pick front matter first, none does now.
On DAZSMA, the one session turn that cited the List of Tables now cites a results page instead, and nothing else moved.
The fix exposes the next problem on sample3: with the contents gone, two archetypes' best match is now the **reference list** (pages 80-81), and one recommended session (capstone, turn 3) cites it.
And on sample3, without the contents page's inflated scores, most first picks now win by a hair: Check B's pooled near-tie rate went from 44% to 62.5%, over M4's 50% line.
Both are reported below; neither is part of G5's pass rule.

**What the code does now.**
- `backend/page_filter.py` holds M4's detector, moved unchanged, plus `removable_pages` (navigation pages before the boundary; nothing when no boundary is found) and `chunk_pdf_without_navigation`.
- The chunker reads every page, counts all their characters for the scanned-PDF check, skips the removable pages, and splits and packs the rest with v1's own `_paragraphs_from_page_text` and `_pack_spans`, imported, not copied.
  Page indices stay the PDF's own.
- `backend/pdf_ingest.py`'s `parse_pdf` calls it, and logs the removed page numbers (numbers only) when there are any.
- `evals/retrieval_checks.py` imports the detector from `backend/page_filter.py`; there is one definition.
- `render.yaml`: `docs/**` and `evals/**` join the backend's `ignoredPaths`.
- `academic_defense_simulator/`: no change (`git diff --name-only main -- academic_defense_simulator` lists nothing).
  Prompts, scoring and `retrieve()` are untouched.
- The v2 backend doesn't use v1's bundled sample sidecar anywhere; the bundled sample PDF appears only in `backend/tests/test_embedder_parity.py`, which still chunks it with v1's chunker.
  The sidecar is unchanged.

### Deviations, with provenance

1. **The runner gained `--chunker {production,v1}`, and its default output changed.**
   With no flag it measures production ingest (now filtered) and writes `evals/v2.0-m5-retrieval-results.json`; `--chunker v1` reproduces M4's file byte for byte.
   So the plain command in the M4 results doc now produces M5's numbers, and M4's are `--chunker v1`.
   The v1 path, `parse_pdf_v1`, is the pre-M5 `parse_pdf` (v1's chunker, same `IngestFailure` mapping), kept in the script rather than in production.
   The M3 live-run validation only runs under `--chunker v1`, since that run predates the filter; on the production chunker every simulated turn is still checked against `retrieve()`.
   The `page_filter` field appears only in production output, so the v1 run stays byte-identical.
2. **G6's premise doesn't hold as stated, and the change is in anyway.**
   The backend's `buildFilter.paths` was already `backend/**`, `academic_defense_simulator/**` and `render.yaml`, so a `docs/` or `evals/` change shouldn't have matched it, and the M4 push (`5142cc6..a50ef1f`) touched none of those paths.
   Claude Code couldn't establish from the repo why the backend redeployed after M4.
   The `ignoredPaths` entries are harmless and make the intent explicit; checklist item 3 checks whether they help.
   This merge itself does redeploy the backend, since it changes `backend/**` and `render.yaml`; that's intended.
3. **The synthetic results page uses whole numbers.**
   The first draft used scores like "4.70", which the detector doesn't count as ending in a page number (the final digits need a space before them), so that page wasn't flagged at all.
   Whole numbers make the fixture what the brief asked for: a page the detector flags and the boundary protects.
   It also means a real results table in decimals isn't at risk from the detector in the first place.
4. **`InsufficientTextError`'s message** in the new chunker is v1's wording with a semicolon for its dash.
   No user sees it: `parse_pdf` replaces it with its own scanned-PDF message, and `total_chars` is identical (tested).
5. **A new ingest log line**, `navigation pages left out of chunking: [...]`, lists 1-based page numbers when pages are removed.

## 3. Concepts map

- **A heuristic detector and its false positives.**
  The detector guesses from a page's shape (most lines end in a number or dotted leaders), not from understanding it, so a page that merely looks like a contents page, such as a results table of counts, also trips it.
  M5 contains that risk by only removing flagged pages before Chapter 1 (`backend/page_filter.py:39` `is_navigation_page`, `:60` `removable_pages`; the test fixture's results page shows a flagged page that is kept).
- **Fail-open vs fail-closed.**
  Fail-open means that when the filter can't decide, it does nothing and the document chunks as before; fail-closed would refuse or strip pages when unsure.
  With no Chapter 1 found, M5 removes nothing, so the worst case is today's behaviour, never lost content (`backend/page_filter.py:65`; `test_no_boundary_means_nothing_is_removed`, `backend/tests/test_page_filter.py:59`).
- **A parity test.**
  It runs the old and new code on the same input and requires identical output, so any difference is a bug rather than a judgement call.
  Here, on documents with no navigation pages, the new chunker must produce v1's exact texts and page ranges (`backend/tests/test_page_filter.py:31`; the happy-path API test also still compares against v1).
- **A single source of truth.**
  The detector exists in one place, the production module, and the eval imports it, so the thing measured is the thing shipped.
  A copy could drift silently; the guard run proved the move changed nothing (`evals/retrieval_checks.py:19`).
- **Why removing pages shifts every later chunk.**
  The packer fills each chunk greedily up to about 2,800 characters and carries a little overlap forward, so taking out pages changes where the first chunk ends, and that change ripples down until a boundary happens to line up again.
  On DAZSMA it realigned before Chapter 1; on sample3 it didn't, so its body chunks changed too (`academic_defense_simulator/rag/chunking.py:126` `_pack_spans`; `backend/page_filter.py:103`).
- **Build filters on Render.**
  A service's `buildFilter` says which changed paths trigger an automatic redeploy: `paths` lists what counts, `ignoredPaths` carves exceptions out of it.
  A redeploy of the free backend means a cold start for visitors, so docs and eval changes shouldn't cause one (`render.yaml:20` `paths`, `:25` `ignoredPaths`, `:30-31` the new entries).
