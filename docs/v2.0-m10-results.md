## 2. Deviations, with provenance

Each of these is Claude's call during the run, made because the API or the build forced it; I haven't confirmed any of them yet.

1. **No total and no "Round X of Y" in the header.** The API sends no total (follow-ups vary the count), so the dots show the questions so far.
2. **No "Up next" status.** The API never says who asks next. Idle cards say "Asked N", "Yet to ask", or "Speaks last" for the Devil's Advocate.
3. **Preparing: the other seats say "Seated", not the canvas's "Reading".** Nothing reads in parallel during `/start`, so "Reading" would be an invented claim.
4. **The ingest summary also reports held-back literature-review passages.** Under `lit_review_access=none` the tagged passages can't be cited, so "passages the panel can cite" would be wrong without subtracting them; the preparing screen says how many were held back and where.

## 3. Concepts map

**GSAP timelines vs CSS transitions.**
A CSS transition animates one property when a class changes; a GSAP timeline places several tweens on one clock, so "card, then question, then source" is one ordered sequence.
I use CSS for hover and focus, and a timeline only for the handoff (`frontend/src/motion/motion.ts:21`).

**`useGSAP` and cleanup.**
`useGSAP` is `useEffect` for GSAP: everything created inside it is recorded in a context and reverted on unmount or when its dependencies change.
With `revertOnUpdate`, each new question starts from clean elements (`frontend/src/motion/motion.ts:22`).

**`gsap.matchMedia` for reduced motion.**
`gsap.matchMedia().add(query, fn)` runs `fn` only while the media query matches and reverts what it made when it stops matching.
Adding under `(prefers-reduced-motion: no-preference)` means no animation exists at all for people who asked for less motion (`frontend/src/motion/motion.ts:24`).

**Object URLs for a local PDF, and `#page=`.**
`URL.createObjectURL(file)` gives a `blob:` URL that points at the file already in the browser's memory, so the viewer opens it without any upload; `revokeObjectURL` frees it.
Appending `#page=N` asks the built-in viewer to open at that page, which desktop Chrome honours and some mobile browsers ignore (`frontend/src/hooks/useObjectUrl.ts:37`, `frontend/src/components/DocumentPanel.tsx:39`).

**Open Graph tags.**
`og:title`, `og:description` and `og:image` are what LinkedIn and others read to draw a link preview; the image URL must be absolute.
`twitter:card=summary_large_image` asks for the big-image layout (`frontend/index.html:19`).

**Print stylesheets.**
CSS inside `@media print` applies only when printing or saving as PDF.
Here it swaps the colour tokens to black on white and drops shadows; the `print:hidden` class hides buttons (`frontend/src/index.css:136`).

**A static fixture replay.**
The recorded defense is a JSON file of real API responses served with the page, read once with a plain `fetch`.
The real screens render from it with a step counter, so the demo can't drift from the product and never touches the server (`frontend/src/components/DemoReplay.tsx:58`).

**`localStorage` with try/catch.**
`localStorage` keeps strings per site across reloads, but it throws in some private windows or when storage is blocked or full.
Every read and write is wrapped, so a failure just means the draft isn't saved (`frontend/src/lib/answerDrafts.ts:13`).
