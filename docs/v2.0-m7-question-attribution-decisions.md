## Part 1 — Locked decisions

Unless noted, Claude proposed each of these in our design conversation on 2026-10-27, and I confirm them by sending this brief.

### J1. The defect
Found in the 2026-10-27 deployed live check on sample3. Question 1 asked how the team handled the power draw of the TMS320C6713 DSP board. That board belongs to Pamungkas & Rais (2022), a study the paper *reviews* on pp. 16–18; the project itself uses an ESP32-S3. The Devil's Advocate then built question 4 on the same mistake.

Retrieval worked as designed. The problem is that the panelist prompt says "one excerpt from the candidate's research document," so the model treats every passage as the candidate's own work, including a literature review that describes other people's systems. A real panel would never make that mistake, and a student would notice immediately.

### J2. The fix: annotate the passage, not the prompt template
- **Detect the literature-review range at ingest,** in `backend/page_filter.py` next to the M5/M6 filters.
  - **Start:** the first line after the front-matter boundary that is a Chapter 2 heading (`CHAPTER 2`/`CHAPTER II`, optionally with a title) or a standalone `Review of Related Literature`/`Literature Review`/`Related Works`/`Related Literature` heading.
  - **End:** the next Chapter 3 heading (`CHAPTER 3`/`CHAPTER III`) or a standalone `Methodology` heading.
  - **Start found but no end →** don't tag anything (fail-open).
- **Tag chunks:**
  - **Both ends inside the range →** "from the literature review".
  - **One end inside →** "partly from the literature review".
  - **No range found →** no tags. Behaviour is exactly as today.
- **Annotate only the text the engine's prompt sees.** In `backend/engine_adapter.py`'s `engine_chunks`, prefix tagged chunks' text with a short note, for example: *"[Note to the panelist: this excerpt is from the candidate's review of related literature. It describes other researchers' work that the candidate cites, not the candidate's own system. Ask about how the candidate used, compared against, or departed from this work.]"* Adjust "partly" accordingly. The exact wording is Code's to draft; it must not mention page numbers.
- **What stays unchanged:**
  - **Retrieval.** Embeddings are computed at ingest from the original text, so the prefix can't move a ranking. That's proven by a guard (J5).
  - **The source reveal.** It shows the original `ChunkMeta` text, without the note.
  - **v1.** `academic_defense_simulator/` isn't touched, and neither is the prompt template.
- **Grounding:** v1's grounding check compares `grounding_reference` against the chunk text, now including the note. The probe reports any `grounding_reference` that only matches note text. That counts as a grounding failure, not a pass.

*Downside I accept:* a document that doesn't title its literature review in a recognisable way gets no notes. Citations of other work inside Chapter 1 aren't covered either.

### J3. Behind a flag
`ADS_ATTRIBUTION_NOTES`, default **off**. The probe runs with the notes forced on and off regardless of the flag. Turning it on in production is my decision after the J4 verdict: an env var on Render, no deploy needed. This lets the merge happen without waiting for my judging.

### J4. Re-verification probe (Day 4 rule) and the pre-committed verdict
Injecting text into the prompt is a prompt change, so it gets a blinded A/B probe on real generations.

**Design:**
- Documents: sample3 and DAZSMA.
- Items: 5 literature-review chunks per document that describe a specific other study (contain an `et al.` or `(Author, YYYY)` citation, chosen evenly spaced, deterministically), × 2 archetypes (Technical Implementation Reviewer, Methodology Expert), at difficulty 3. That's **20 items per arm**.
- **Before arm:** no notes. **After arm:** notes on.
- **Control:** 3 own-work chunks from Chapter 3 per document × the same 2 archetypes, **after arm only**, for 12 items. Untagged chunks have no note, so this checks the model doesn't start treating the candidate's own work as cited.
- Generation uses the production question path: same template, model and settings, with retrieval bypassed by fixing the chunk. Reuse `scripts/probe_question_gen.py` where it fits.

**Blinded judging (mine, because Claude drafted the note):** Code writes a shuffled judging sheet with no arm labels: question, passage, page range, and a blank label. The key goes in a separate file; both are gitignored, because they contain passage text. For each item I mark:
- **M:** treats cited work as the candidate's own;
- **C:** treats the candidate's own work as cited;
- **OK:** neither;
- **?:** unsure.

`?` counts against the after arm and for the before arm, so the scoring is conservative.

**Verdict, written before any data exists. A script scores my labels and prints which branch applies:**
- **Before arm M ≤ 3 of 20 →** the problem is rare. Don't turn the flag on; record it as a one-off.
- **Before arm M ≥ 4, after arm M ≤ 1 of 20, control C ≤ 1 of 12, and grounding passes in the after arm ≥ before − 2 →** **turn the flag on.**
- **Anything else** (an after arm of 2+, a control that fails, or grounding drops) **→** leave it off. Attribution goes back to design in chat. No re-tries with new wording inside M7.
