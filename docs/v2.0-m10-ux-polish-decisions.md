## Part 1 — Locked decisions

Unless noted, Claude proposed each of these in our design conversations on 2026-10-28, and I confirm them by sending this brief.

### N1. Palette: Bench stays
The current Bench tokens (M8 K6) stay as they are. The canvas's Red Pen and Archive schemes are parked for later. Port the canvas screens with `scheme=bench`. New elements use existing tokens only; no new colours.

### N2. Session layout (canvas `Main.dc.html`)
- **Header, spread across the width.**
  - **Left:** the wordmark and "‹document title› · ‹defense type›".
  - **Middle:** "Question N" and progress dots. Show "Round X of Y" or a total **only if the API exposes it**; never invent a total.
  - **Right:** the voice control (N9), "Your document" (N4) and "End session".
  - It wraps cleanly at phone width.
- **End session:** an in-app confirm (not `window.confirm`), then `DELETE /sessions/{id}`, then back to the start screen.
- **Panel:** four equal cards in a `repeat(auto-fit, minmax(240px, 1fr))` grid (2×2 on phones). Each card has **v1's avatar PNG**, the name and the role on the left, and the status on the right ("Speaking", "Up next", "Asked N", "Speaks last"). Only the active card is lit (accent border, soft background, dot). The Devil's Advocate's card has a dashed outline. This replaces M8's centered bench row.

### N3. Start screen (canvas `Start.dc.html`)
- **Two columns:** the hero and the no-PDF paths (N5) on the left; the form on the right. It stacks on phones.
- **Form:**
  - a drag-and-drop PDF zone (with the click-to-browse input kept, plus the size and page limits);
  - the defense type as three toggle buttons;
  - **panel presets** (N7);
  - difficulty 1–5 in one row;
  - the domain and title fields folded under "Optional details", closed by default;
  - the quota line in the header.

### N4. Open my own PDF at the cited page
- Keep an object URL of the uploaded `File` for the session. A side panel on desktop, or a full-screen sheet on phones, shows it in the browser's built-in viewer at `#page=N`.
- **"Open at page N in your PDF"** sits on the source-reveal card. **"Your document"** in the header opens page 1, or the last revealed page.
- Nothing is uploaded again. Revoke the URL when the session ends or the page unloads.
- If the file is gone (after a reload, say), hide the buttons. Where `#page=` is ignored (some mobile browsers), it just opens the PDF.
- The panel has prev/next/close controls only if they're reliable with the built-in viewer. Otherwise, just close.

### N5. A demo path with no upload
- **"Read a recorded defense":** one real defense on the **bundled AniCheck sample** (already public in the repo), recorded once from the real API: every response, including the questions, sources, evaluations and report. It's stored as a static fixture under `frontend/public/demo/`, then replayed through the real screens with a "Next" control and a visible "Recorded demo" label.
  - Replay makes **no backend calls** and costs no quota. Voice in replay: browser voice or none, never MiMo.
- **Answers in the recording** are written by Code, grounded in the AniCheck paper, and **deliberately mixed** (two strong, one partial, one weak), so adaptive difficulty and the report's gaps show. The replay says plainly: "Answers in this recording were written to demonstrate the panel."
- **"Try it with the sample paper":** starts a normal live defense with the AniCheck PDF loaded from `frontend/public/sample/`. It says it uses one of today's defenses. If the AniCheck PDF isn't in the repo as a file, drop this button and record why (the recorded demo still ships).

### N6. "The panel is reading your paper" (canvas `Preparing.dc.html`)
- **Real numbers only.** Show the page count, the passages the panel can cite, and what was skipped (contents/navigation pages from M5, the reference list from M6), with page ranges. Add these to the session status as **additive** fields computed at ingest, which already knows them. No invented numbers.
- **Per panelist:** before `/start` returns, show each seat's role with **what that role looks for**: one short line per archetype, kept as frontend copy (e.g. Technical Implementation: "build decisions and technical trade-offs"). It must faithfully summarise v1's `archetype_focus`. Names appear when `/start` returns. No made-up "reading Chapter 3" claims.
- The first seat shows "Writing question 1"; the Devil's Advocate shows "Speaks last".

### N7. Panel presets (my choice A)
- Presets are frontend data that map to **existing** archetype keys. Nothing changes in v1 or the backend.
- **The Literature & Theory Specialist is in no preset** while `lit_review_access=none` (M9). It stays under Custom with a note: "Doesn't read the literature review in this version."

| Preset | Panelists (+ Devil's Advocate always) |
|---|---|
| Recommended for a thesis | Methodology · Problem & Objectives · Results & Conclusions |
| Recommended for a capstone | Technical Implementation · Methodology · Results & Conclusions |
| Recommended for "other" | Methodology · Problem & Objectives · Ethics & Practicality |
| Technical-heavy | Technical Implementation · Methodology · Statistical Analysis |
| Research-heavy | Problem & Objectives · Statistical Analysis · Results & Conclusions |
| Real-world impact | Industry Practice · Ethics & Practicality · Technical Implementation |
| Custom | Up to 3 of the full list |

- The first row shown is the "Recommended" row for the selected defense type.
- **Validity test:** every preset must be accepted by `/panel-options` for each defense type it's offered for. A preset that isn't valid for a type is hidden for that type, not sent.

### N8. Answer-box comforts
- **Ctrl/Cmd+Enter** sends.
- A quiet word count.
- **The draft is saved in `localStorage`**, keyed by session and turn, wrapped in try/catch, so it degrades silently if storage throws. It's cleared on a successful send.

### N9. Voice control in the header
A menu with Panel voice / Browser voice / No voice, switchable mid-session. Switching to Panel voice the first time in a session shows the M3b disclosure. Status and fallback behaviour are unchanged.

### N10. Transcript drawer
Earlier turns, each with the question, my answer and the source pages. **No scores** (sealed, M8 K7). Focus is trapped while it's open, and Esc closes it.

### N11. Printable report
A "Save as PDF" button calls `window.print()`, with a print stylesheet:
- the headline and dimension scores;
- every question card expanded, with passages and highlights;
- no navigation, drawers or buttons;
- the paper card prints legibly in black and white.

### N12. Share preview and identity
- In `index.html`: a real `<title>`, a description, `og:title`/`og:description`/`og:image`, and `twitter:card=summary_large_image`.
- A favicon (SVG plus a PNG fallback).
- The `og:image` is a 1200×630 PNG in Bench style: the wordmark plus "Face a panel that has read your paper." Generate it from a static HTML file with the existing screenshot harness, and commit the PNG.
- Absolute URLs come from a build-time `VITE_SITE_URL` (set in `render.yaml` to the static site's URL).

### N13. Motion: GSAP is allowed, narrowly (supersedes M8 K9's "no dependency" line)
- **Allowed dependencies:** `gsap` and `@gsap/react` (`useGSAP`). GSAP and all its plugins are free, including commercial use.
- **Only for choreography that shows state:**
  - the **handoff** (the active card dims, the next one lights, then the question reveals) as one timeline;
  - the preparing screen's seats staggering in;
  - the source reveal sliding in;
  - replay transitions in the recorded demo.
- **Not allowed:** ScrollTrigger or scroll effects, landing-page flourishes, anything decorative.
- Hover and focus transitions stay plain CSS.
- **Reduced motion:** with `prefers-reduced-motion`, no GSAP animation runs (`gsap.matchMedia`), and everything appears in its final state.
- Clean up every animation on unmount (`useGSAP` scope). Report the bundle-size change.
- **If the GSAP agent skills are installed** in this Claude Code session (`greensock/gsap-skills`), use `gsap-core`, `gsap-timeline`, `gsap-react` and `gsap-performance` for patterns. If they aren't, proceed anyway; they are guidance, not a requirement.

*Downside I accept:* one more dependency (about 30 KB gzipped), and two motion systems (CSS for micro-interactions, GSAP for choreography).

### N14. Unchanged
`AnswerScore`, the rubric, prompts, retrieval and routing, the voice map, the backend's error contract (additive fields only), the M3 D16 error states, and M8's sealed scores.
