## 3. Concepts map

**Components and props, and what JSX compiles to.**
A component is a function that takes one object of inputs (props) and returns what to draw, so `QuotaLine` gets `{ quota }` and decides between "7 of 11 defenses left today" and nothing.
JSX like `<Card className="space-y-2">` is compiled by Vite into a function call, `jsx(Card, { className: 'space-y-2', children })`, so it's JavaScript underneath, not HTML.
See `frontend/src/components/ui.tsx:4` (`Card`) and `frontend/src/components/QuotaLine.tsx:6`.

**`useState` vs `useReducer`.**
`useState` holds one value a component changes directly, like the preparing screen's stage counter.
`useReducer` holds state that changes in many related ways, and routes every change through one pure function (`reducer(state, action)`), which is why the whole defense flow is one reducer that tests can drive without React.
See `frontend/src/components/DefenseScreens.tsx:26` and `frontend/src/state/useFlow.ts:30`.

**Discriminated unions and `switch` narrowing.**
`Phase` is a union of object types that all share a `kind` field with a different literal value, so the compiler knows exactly which other fields exist for each kind.
Inside `switch (phase.kind)`, each `case` narrows `phase` to that one variant, so `phase.sessionId` compiles in `case 'queued'` and is an error in `case 'configuring'`.
See `frontend/src/state/flow.ts:47` and `frontend/src/App.tsx:16`.

**`useEffect` with cleanup, and StrictMode.**
An effect runs after React draws, for work outside rendering such as a timer, and the function it returns is the cleanup that React calls before the effect runs again or the component goes away, which is how the keep-alive interval stops when the defense ends.
In development, `StrictMode` mounts, cleans up and re-runs every effect once on purpose, to catch effects whose cleanup is missing, which is why user-triggered POSTs run from click handlers and not from effects here.
See `frontend/src/hooks/useKeepAlive.ts:9`, `frontend/src/state/useFlow.ts:60` (polling) and `frontend/src/main.tsx:10`.

**`async`/`await` with `fetch`, and XHR for upload progress.**
`await fetch(...)` pauses that function until the response arrives without freezing the page, and the client turns each response into either the typed body or an `ApiError`.
`fetch` can't report how much of a request body has been sent, so the upload uses `XMLHttpRequest`, whose `upload.onprogress` event drives the progress bar.
See `frontend/src/api/client.ts:92` (`request`), `:129` (`createSession`) and `:137`.

**Tailwind utility classes and the theme config.**
Each class is one CSS rule (`rounded-lg` is `border-radius`, `px-4` is horizontal padding, `sm:grid-cols-2` is two grid columns from 640 px up), written beside the markup it styles.
The `@theme` block defines the design tokens, and each `--color-*` there becomes classes such as `bg-brand` or `border-accent-methodology`.
See `frontend/src/index.css:5` and `frontend/src/components/ui.tsx:15`.

**Vite env vars.**
Vite replaces `import.meta.env.VITE_API_BASE_URL` with its literal value when it builds, so the backend URL is written into the JavaScript file every visitor downloads.
That's why only `VITE_`-prefixed variables reach the browser and none of them may ever hold a secret.
See `frontend/src/env.d.ts:5`, `frontend/src/api/client.ts:37` and `render.yaml:59`.

**What `npm run build` outputs, and what Render serves.**
`npm run build` type-checks and then writes `frontend/dist/`: one `index.html`, one hashed JS file and one hashed CSS file (257 kB and 17 kB before gzip), plus `public/` copied as-is, including `icons/`.
Render's static site runs that build and serves `dist/` as plain files from its CDN, with no server code, which is why every dynamic thing goes through the backend API.
See `frontend/package.json:8` and `render.yaml:47-49`.

**Open items for M3b and later:**
- **A lost response can strand a turn.**
  If `/answers` or `/start` succeeds on the server but the response never reaches the browser, "Try again" either gets a 409 (swallowed by D16, so the screen waits forever) or, once the lock is free, sends the same text as the answer to the next question.
  No endpoint returns the pending question, and answers carry no turn number.
  The fix I'd consider: `AnswerRequest` carries the turn it answers and the server refuses a mismatch, plus a `GET` for the current question.
- **"You've used your 3 defenses for today" hardcodes 3**, D16's copy, while `ADS_PER_IP_DAILY_STARTS` can change it; the 429 body could carry the limit.
- **`ADS_CORS_ORIGINS` must be set on `ads-backend`** once the static site exists, or every browser call fails.
- **Seats on the preparing screen** appear only if `/panel-options` loaded; otherwise the screen shows the staged copy alone.
