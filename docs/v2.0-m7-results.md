## 3. Concepts map

- **Prompt context vs prompt template.**
  The template is the fixed instruction text with slots (`academic_defense_simulator/prompts/panelist_prompts.py:81`); the context is what fills a slot at run time, like `{retrieved_chunk}` (line 112).
  M7 changes only the context, by prefixing the chunk text, so v1's template stays locked (`backend/engine_adapter.py:72`).
- **Why annotating the text the prompt sees can't move retrieval.**
  Retrieval compares the query against the session matrix, which was embedded from the original chunk text at ingest (`backend/ingest_queue.py:190`).
  The note is added later to the engine's copy of the text only (`backend/engine_adapter.py:90`), and J5's byte-identical eval confirms it.
- **Blinded A/B judging, and why I judge.**
  Mixing before and after generations without labels means my judgment can't lean toward the version I expect to win (`scripts/probe_attribution.py:80`, the shuffle seed; the key is a separate file).
  I judge because Claude wrote the note, and a model grading its own fix is the bias the blinding is there to stop.
- **Conservative scoring of "unsure".**
  An unsure label counts in the direction that makes "turn the flag on" harder: against the after arm and the control, and never as evidence the problem exists (`scripts/score_attribution_judging.py:101`).
  So a flag-on verdict can't come from my hesitation.
- **Feature flags as a release valve.**
  The code ships switched off and an env var turns it on without a deploy (`backend/settings.py:68`).
  That's what lets the merge wait only on the tests, and lets the flag decision wait on the judging.
- **faulthandler.**
  Python's faulthandler can print every thread's stack from a timer, even while the code is stuck, and pytest arms it per test with `faulthandler_timeout` (`pytest.ini:8`).
  If a backend test hangs again like M6's did, the log will show where.

## 5. Revision after my decisions of 2026-10-27

### J2 is superseded

Claude's J2 design made any Chapter 2 heading start the literature review.
Claude found the problem while selecting probe items (section 2): DAZSMA's Chapter 2 is the team's own system design.
I decided the replacement on 2026-10-27, and this is it.

A chunk is tagged only if both hold:
- **(a)** it lies in a section whose heading names the literature: "Review of Related Literature", "Literature Review", "Related Works" or "Related Literature", standalone or as a chapter's title.
  A bare "CHAPTER 2" no longer starts a range.
  The end is unchanged: the next Chapter 3 or "Methodology" heading.
- **(b)** the chunk's own text cites a study: "et al.", "(Author, YYYY)", or a numbered reference like "[12]".

In code: `_STANDALONE_LITERATURE_HEADING` and `_CHAPTER_LITERATURE_HEADING` start the range, and `cites_a_study` is (b), checked in `_attribution` (all in `backend/page_filter.py`).
The "full" and "partly" tags work as before, inside those two conditions.

Two readings of my wording, both Claude's:
- **A heading may go on with "and" and up to three words** when the line is set as a heading (all capitals, or its longer words capitalised).
  The standard Philippine title "REVIEW OF RELATED LITERATURE AND STUDIES" names the literature, and it's how sample3 and the bundled sample head theirs.
  "Review of related literature and studies shows that..." is a sentence, and is rejected.
- **A narrative citation alone, "Reyes (2021)", isn't a citation for (b).**
  It isn't in my list; "Reyes et al. (2021)" and "(Reyes, 2021)" are.

Tests (`backend/tests/test_page_filter.py`):
- **Headings:** 10 accepted start headings; 11 rejected, including bare "CHAPTER 2", "CHAPTER 2: SYSTEM DESIGN", "Related Studies", a sentence, and contents lines.
- **Citations:** 6 citation forms and 5 non-citations.
- **Tagging:** a review chunk that cites nothing goes untagged; a bare "CHAPTER 2" over cited text starts nothing; the bundled sample tags only its citing review page.

With the conftest's cited text now saying "Santos et al. (2021)", the API tests in `test_attribution_notes.py` pass unchanged.
